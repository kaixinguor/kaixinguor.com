DeepSeek 开源 Super-agent 架构：AI 自己找 Bug、自己提 PR

10 月 31 日晚，DeepSeek 公开了一套面向个人 Agent 的底座架构思路「Super-agent：迈向更自主的 Agent 系统」，并放出了原型仓库 dsh-superagent-prototype。它要解决的问题不是「模型会不会做」，而是「一个人同时只能跟进三到五个会话」：任务散在群聊、代码平台和邮件里，上下文要靠人来回搬运。

架构分两层：上层 Router 接消息、分任务、维护全局上下文；下层是一组 Worker，各自执行、互不干扰。Worker 可以「订阅」某个 GitHub PR，后续评论直接进这个 Worker，不再经 Router 转发。消息侧做了两级过滤，先用程序规则筛掉无关消息，再让模型判断剩下的事件要不要行动。

官方给的初步实验是：模拟约 300 条消息、20 项工作请求的协作环境，重复 5 次，Super-agent 任务完成时间中位数 12.4 分钟、95 分位 15.7 分钟；传统单会话方案在提示中性时，95 分位达到 29.5 分钟。代价也写了出来：取消事件直通机制后，Router 决策次数增加约 30%，读取缓存 token 增加约 37%。

另外两个工程细节值得记：一是异步 ReAct Loop，已在 DeepSeek Harness 中实现但尚未默认开启；二是计算、状态与执行环境分离，加上独立的 Watchdog 监督循环与异常恢复。文章之外，目前能验证的只有原型仓库，还没有对外可用的产品。

看点这份架构真正改动的是「谁记住进度」。过去是人记着哪个会话进行到哪一步，现在由 Router 维护全局上下文、Worker 各自订阅后续事件——省下的是人的注意力，花掉的是 token 与调度复杂度。12.4 分钟对 29.5 分钟这个对比，测的是多任务吞吐，不是单任务质量；等它开放给外部使用时，要看的第一个指标也不是完成时间，而是「主动行动」的误报率：一个会自己找 Bug 的 Agent，找错的成本由谁承担。

腾讯 Hy4 对阿里 Qwen4：同代旗舰，同一周上场

10 月 31 日，字母榜在钛媒体发文称：腾讯刚宣布混元 Hy4 正式版即将发布，阿里则在欧洲放出 Qwen4 下周登场的消息。两家过去习惯错开档期，这一次版本号相同、窗口相同，都押注 Agent 与真实生产力。

按文中披露的预览版信息，Qwen4 的架构先在 Qwen3.8-Flash-Next 上验证：注意力机制结合 Gated DeltaNet 与 Qwen Sparse Attention，主干 125B 参数、另加 51B 的 N-gram Embedding，每个 token 激活 6B，训练成本为 Qwen3.7-Plus 的九分之一。真正要在 Qwen4 上回答的是，这套架构能不能延续到旗舰规模。

另一条线是 RSI。阿里称 Qwen3.8-Max 已能在人类几乎零参与下自主搭建训练流程、构造数据、设计实验并定位缺陷，持续迭代超过一个月、完成 33 轮有效迭代，Artificial Analysis 评测得分从 40 提升到 45；推理侧自主适配平头哥新架构后，单实例吞吐提升 96%；在芯片协同设计中，模型依据总线模块规范自迭代 60 小时、调用 EDA 工具超过一万次，把物理实现面积缩减 42%。

Hy4 这边，腾讯强调的是长程任务与真实生产力、思维链效率，并首次引入视觉理解，同时推出 Hy4 Flash 承接高频调用。两边的组织背景也被摆上台面：Qwen4 是刘大一恒接任后的第一个完整代际，Hy4 是姚顺雨重建预训练与强化学习基础设施后的正式产品。

看点同代对决最有价值的部分不是跑分，而是两家对「Agent 能力」的定义是否一致：阿里把筹码压在长程任务成功率与 RSI 摊薄训练成本，腾讯压在视觉输入与产品场景回灌。定义不同，榜单就不可比——真正能分出胜负的，是同一个真实任务在两边的完成率、返工率和每任务成本。RSI 那组数字（33 轮迭代、面积 -42%）如果可复现，改变的不是某一代模型的排名，而是下一代的研发工时表。

OpenAI 要给安全出报表：首期《社区安全报告》2027 年初发布

据 IT之家 10 月 31 日报道，OpenAI 于当地时间 10 月 30 日发布博文，承诺定期发布《社区安全报告》（Community Safety Report），系统公开暴力预防、其他社区安全议题以及各项防护机制的实际成效。首期报告将于 2027 年初发布，覆盖 2026 年下半年数据，此后每半年更新一次。

已经披露的数字是：仅在 2026 年第三季度，OpenAI 就向执法部门移交了 200 余起案件线索。

产品侧同步收紧。针对既往大规模恶性袭击事件及凶手，ChatGPT 只提供极度精简的信息，限制对作案细节的复盘，包括武器参数、获取途径以及可能助长凶手恶名的伤害规模对比，且不区分用户年龄与提问动机；对青少年可获取的涉枪涉武器信息也加了一道更严的门槛，即便提问表面无害。

更实质的改动是断路器：当对话显示用户开始执念于暴力、或萌生严重伤害他人的念头时，ChatGPT 可以自动终止当前对话；同一账户因此被多次中断，可能被临时冻结。OpenAI 称正在开发新功能，在青少年账户被临时冻结时第一时间通知家长。

看点把安全从政策文本变成半年一份的报表，好处是可核查，代价是可考核：一旦公开中止率、移交数、误伤率，就会被拿来和其他实验室比，也会被拿来和「不中断」的用户体验比。自动终止对话是一条硬边界，它把判断权从模型输出挪到了账户层——问题随之变成：误判一次，用户丢掉的是对话还是账号；申诉通道在哪。这些不会写进首期报告，但会决定它有没有人信。

DeepSeek open-sources a Super-agent design: agents that file their own pull requests

On the evening of October 31, DeepSeek published an engineering note titled “Super-agent: toward more autonomous agent systems” along with a prototype repository, dsh-superagent-prototype. The problem it targets is not whether a model can do a task, but that a person can only track three to five live sessions; context has to be carried by hand between chat, code and mail.

The design has two layers. A router receives messages, assigns work and keeps global context; a pool of workers executes in parallel without blocking each other. A worker can subscribe to a pull request, so later review comments go straight to it instead of back through the router. Incoming messages pass two filters: programmatic rules drop noise, then a model decides whether the rest deserves action.

The reported experiment simulated a workspace with roughly 300 messages and 20 work requests over five runs. Super-agent finished with a median of 12.4 minutes and a 95th percentile of 15.7 minutes; the single-session baseline reached 29.5 minutes at the 95th percentile under a neutral prompt. The cost is stated too: disabling event pass-through raised router decisions by about 30% and cached-token reads by about 37%.

Two engineering details are worth noting. An asynchronous ReAct loop already exists in DeepSeek Harness but is not on by default, and compute, state and execution environments are separated, with a watchdog that watches for loops, drift and failures. Beyond the note, only the prototype repository can be verified; there is no public product.

Why it mattersThe real change is who remembers progress. Instead of a person tracking where each thread stands, a router holds global context and workers subscribe to follow-ups. That saves attention and spends tokens and scheduling complexity. The 12.4-versus-29.5 comparison measures multi-task throughput, not per-task quality. When outsiders get access, the first number to watch will not be completion time but the false-positive rate of “acting on its own” — because when an agent finds a bug by itself, someone has to pay for the ones it invents.

Anthropic renames its top tiers and drops the five-hour window for Ultra

Anthropic reshuffled its Claude subscriptions on October 31. Max 5x and Max 20x become Max and Ultra at the same $100 and $200 a month. The substantive change sits in the $200 tier: verified Ultra accounts no longer wait for a five-hour window to reset and can work continuously within their weekly allowance.

Everything else holds. Weekly usage stays at ten times Pro, new models and features arrive first, and Claude Code plus long-running background tasks are supported. Existing subscribers migrate automatically; new accounts wait for verification, which is assessed from account and payment history.

Mike Overell, who runs subscription products, explained the rename. The original 20x referred to a 20-times allowance inside a single five-hour window, but once weekly caps arrived the weekly allowance was only ten times Pro. He apologised for the earlier framing.

The timing is awkward: OpenAI doubled Pro limits a day earlier. In June, the Wall Street Journal reported a consumer lawsuit over how the high-priced tiers advertised their limits, centred on the real usable volume of Max 5x and Max 20x.

Why it mattersRemoving the five-hour window looks like loosening, but it swaps time slicing for a weekly total. Users are interrupted less; the total is unchanged, so heavy users simply spend the same allowance in one continuous stretch. For Anthropic this answers a lawsuit and a long-running complaint, and it also clears the way for long-horizon agent work — being cut off mid-task is a product defect, not a UX preference. The place to watch is what happens when the weekly allowance runs out, because that is where the real price boundary sits.
