# 每日生成任务 · 经济日报（给定时 Agent 的作业说明）

> 每天 09:30（Asia/Shanghai）的定时任务要执行的内容。
> 工作目录：站点仓库根目录（服务器上是 `/opt/kaixinguor/site`，本机是 `~/deepseek-harness/web-kaixinguor.com/site`）。
> 源稿与成品都在 `daily-economy/`（与 `daily-ai/` 平级）。

这份说明和 `每日生成任务.md`（AI 日报）是一对：流程一样，选题口径不同。

## 0. 先做幂等检查

```bash
cd /opt/kaixinguor/site
TZ=Asia/Shanghai date '+%F %T %Z'
git pull --ff-only

NOW="$(TZ=Asia/Shanghai date +%H%M)"
if [ "$NOW" -lt 0930 ]; then
  KAIXINGUOR_NOTIFY_NAME="经济日报" /opt/kaixinguor/bin/notify.sh info "经济日报：当前早于 09:30，跳过补跑，等待今天 09:30"
  exit 0
fi

DATE="$(TZ=Asia/Shanghai date +%F)"
```

如果 `daily-economy/$DATE.html` 与 `daily-economy/$DATE-en.html` 都存在且非空：

- 不要重复生成、不要重复提交；
- `notify.sh success "经济日报 $DATE 已存在，跳过重复生成"`；
- 结束。

### 0.1 手动触发时（当前状态）

服务器还没部署，日报是**手动跑**的：人发一句「出今天的经济日报」，Agent 照这份说明执行。

手动跑的时候，上面第 0 节的两条规则要跳过：

- **不要**因为「早于 09:30」就退出——手动跑就是现在想跑；
- **不要**因为「今天已经有了」就跳过——手动重跑是有意的。`publish-economy` 会覆盖同一天的文件，不会追加，期号沿用已有的。

其余照旧：时间窗口、检索与核验、和 AI 日报的分工、双语、链接检查、发布与通知。

## 1. 时间窗口

- 窗口不是「现在往前推 24 小时」，而是**上一期的终点 → 现在**，两期首尾相接。
- 开工前先跑：

  ```bash
  node scripts/coverage.mjs window --section economy
  ```

  它会打印本期应该用的 `start` / `end`：`start` 就是上一期的 `windowEnd`。
- **同一天重跑**：如果当天页面已经存在，`window` 会直接打印当天已记录的窗口——沿用，不要按当前时间重算；改了窗口会被发布检查拒绝。
- 窗口**不能重叠**，也**不能留空档**：重叠会让同一件事被写两遍，空档会漏新闻。发布脚本会检查，重叠直接拒绝发布。
- 只收**发布时间**落在这个窗口内的报道。页面上没有时间就打开原文确认；确认不了就放弃。
- 不把前一天的旧闻重新包装。

## 2. 检索与核验

至少做 3 轮、累计 10 个以上不同角度的查询。经济这条线建议按下面的角度铺：

- **央行与利率**：美联储 / 欧央行 / 日本央行 / 加拿大、英国、澳洲；议息结果、投票分歧、前瞻指引、资产负债表
- **价格与增长**：CPI、PCE、GDP、PMI、就业、社融、进出口、房价
- **财政与监管**：预算、国债发行、关税、行业整顿、处罚、法案
- **能源与大宗**：原油、天然气、铜、运价、储备释放
- **公司与资本**：财报、并购、IPO、评级调整、回购
- **国内政策**：发改委、财政部、央行、证监会、地方政府的文件与发布会

每条候选都要：

1. **先打开原文，再决定收不收。** 打不开的一律不收录——包括 403 / 反爬、登录墙、付费墙、只有搜索摘要的情况。
2. 打不开就**整条删掉**，不要用转载顶替、不要凭标题补写正文、不要猜数字。
3. 打开后核对：标题、发布时间、正文首段是否与你要写的那件事一致。
4. 记录**时间（MM/DD HH:MM，北京时间）**、来源名、原文链接。
5. 优先原始来源（央行、统计局、发改委、交易所、公司公告、法案原文）；只有二传来源时，在正文里写清楚「据……报道」。
6. 链接发布前会由脚本逐条请求，非 2xx 直接拦住、不落盘。

### 2.1 来源分级：只收一级和二级

> 这一节和AI 日报那份作业说明的同名章节保持一致。改规则时两份一起改，别只改一份。

| 级别 | 是什么 | 怎么用 |
|---|---|---|
| **一级** | 央行、统计局、发改委、财政部、交易所、公司公告、法案原文、国际组织新闻稿 | 优先。数字以它为准 |
| **二级** | 权威媒体的原创报道：新华社 / 新华财经、证券时报、中国基金报、中国证券报、央广、央视财经等 | 可用。正文里写清「据……」 |
| **三级** | 转载、聚合、快讯汇编、门户二手整理、自媒体 | 不用 |
| **不可确认** | 打不开、读不到标题、看不到发布时间、页面是空壳 | **一律剔除，不讨论** |

四条硬规则：

1. **同一件事有一级来源时，链接给一级。** 例：央行公开市场操作，链接给 pbc.gov.cn 的《公开市场业务交易公告》，不是转述它的媒体稿。
2. **一级来源只覆盖部分事实时，正文里用行内链接补第二个来源。** 例：公告写了「开展 1 万亿元隔夜逆回购」，但没写「当日到期 1 万亿元」——后者在正文里挂一个媒体的行内链接，不硬塞进同一条。
3. **脚本报「读不到标题」的链接，必须处理掉。** 顺序是：换到能读的版本（官方全文 / 大站镜像）→ 在正文补一个可验证的镜像 → 都不行就删掉这条。
4. **门户转载稿按三级算，但可以当「镜像」用。** 它证明这篇报道确实存在、正文可读；原始出处仍写作者媒体。

> 一条判据：把链接发给别人，他点开能不能在十秒内看到标题、发布时间和那组数字。看不到，就不该出现在版面上。

### 2.2 经济这条线特有的五个坑

1. **口径。** 同比 / 环比、名义 / 实际、百分比 / 百分点，写错一个就是两种意思。「上升 10.1 个百分点」不是「上升 10.1%」。
2. **公告里的「应」和「实」。** 成品油「按机制应涨 440 元、实际上调 345 元」——机制算出来的数和实际执行的数是两件事，差额去哪了才是新闻。
3. **旧闻翻新。** 政府网站的老公告、往年的「10 月 30 日」文章，标题里全是今天的日期。**日期必须点开看**，2024 年的稿子长得和今天一模一样。
4. **「据测算」「据机构」。** 券商测算不是统计口径。写「某券商测算」，不要写「数据显示」。
5. **境外媒体转述国内数据。** 中间可能已经错了一轮。能回溯到统计局 / 央行 / 交易所原文的，一律回溯。

### 2.3 去重：同一件事只写一次

> 这一节和 AI 日报那份作业说明的同名章节保持一致。

**什么算同一件事**：同一个主体（公司 / 机构 / 产品 / 法案）+ 同一个动作，或同一组数字。即使媒体不同、标题不同、发布时间不同，也算同一件事。典型例子：10/31 已经写过「央行把政策利率锚在隔夜」，11/02 再写「政策利率换锚」就是重复，哪怕换成了人民网的解读稿。

- 生成前先看最近 7 期的头条与标题；`node scripts/coverage.mjs report` 会列出跨期相似对，以及同一天 AI 日报写了什么。
- 发布脚本默认跑 `coverage.mjs check`：同一版块的往期重复、窗口重叠会直接拒绝落盘；**同一天另一个版块的重叠只提示、不拦发布**——同一件事可以在两份里各写一次，但要写出各自领域关心的角度和数字。
- 命中后的处理顺序：
  1. 优先删掉，换一条当天的新事件；
  2. 确实是追更（新进展、新数字、新决定），给卡片加 `data-followup="旧闻日期"`，并在正文写出至少一个旧条目没有的数字 / 型号；
  3. 只有确实要带病发布时才加 `--allow-overlap`，并在通知里说明原因。
- 不要用「不同媒体各写一遍」冒充多条新闻；同一事件最多一条。
- 窗口重叠是重复的第一大来源：先按第 1 节把窗口接上，再谈选条。

## 3. 和 AI 日报的分工（最容易被忽略的一条）

每天 09:00 已经发过一份 AI 日报。**头条尽量不撞，正文可以重叠，但要换一个问题。**

例：AI 日报写 Anthropic 的算力账单，经济日报就写它的招股书怎么给算力定价、承诺的久期如何压住现金流；同一件事、两组不同的数字。重叠不拦发布，拦的是「换个说法重发一遍」。

开工前先读 `daily-ai/$DATE.html`（如果存在），记住它写了哪 9 条、头条是什么、看点落在哪。

分工是：

| | AI 日报 | 经济日报 |
|---|---|---|
| 问的问题 | 谁发布了什么，能力到了哪一步 | 这笔钱从哪来，记在谁的表上，谁承担成本，价格由谁定 |
| 典型角度 | 模型、产品、融资额、榜单 | 资本开支与现金流、利率、通胀、会计口径、监管成本、就业与工资 |

两边都要写同一件事时，经济日报必须给出**不同的问题**——比如 AI 日报写 Alphabet 跌了多少，经济日报就写「财报把它记成资产、市场把它记成风险，两条规则的差别在哪」。

**拿不出不同角度就不写，换一条。** 宁可少一条，不要换个说法重发一遍。

## 4. 选条与结构

- 三个栏目，按这个顺序：
  1. 货币与政策（`data-c="macro"`）
  2. 增长与结构（`data-c="growth"`）
  3. 产业与公司（`data-c="industry"`）
- **条数不固定，按当天的信息密度。** 5–9 条是常态；像「四家央行同一周开会」这种日子可以到 9 条；没有密度就 5 条。
- **少于 4 条就不发**，发一条通知写明原因。不要为了凑数把旧闻、传闻、没有原文的东西塞进来。
- **不设「短讯 / 别处」栏。** 每条都是卡片，每条都必须有可打开的原文链接。收不进来的，就是不收。
- 每个栏目至少 1 条；单个栏目最多 4 条。
- 头条：当天最能量化、最影响定价的那条，放在 01 或 02。
- 每张卡片必须有：
  - 时间（MM/DD HH:MM 或只有 MM/DD）
  - 来源名 + 原文链接
  - 标题（陈述句，不用「震惊」「炸裂」）
  - 3–5 段事实，**带具体数字**
  - 1 段「看点」

**看点写什么**：写机制，不写态度。三选一——

- 这笔钱去哪了 / 记在谁的表上；
- 成本最后落在谁身上（居民、企业、财政、下一代）；
- 这个数字改变了哪个原本的判断。

不要写「值得关注」「拭目以待」「未来可期」，不要做涨跌和点位预测，不要把正文复述一遍。

### 4.1 写作视角：以经济学家的眼睛看

写「看点」之前先选角色：**经济日报的作者是一个做宏观与产业研究的经济学家**——关心价格、激励、资产负债表和久期，不关心产品功能。

他会这样问：

- 钱从哪来、记在谁的表上：政府、企业、居民，还是下一代；
- 口径是什么：同比还是环比、名义还是实际、百分比还是百分点；
- 谁的收入变成谁的成本，价格由谁定；
- 这个安排能不能持续：久期多长、靠什么续、利率变了会怎样。

同一个事件和 AI 日报撞上时不用回避：AI 日报写「这是怎么做到的」，经济日报写「这笔钱怎么记、谁来付、多久要还」。

**主视角与副视角。** 每条卡片有一个主视角（本份日报的角色），「看点」末尾可以加**一句**副视角——只在两件事同时成立时才加：

1. 这件事在另一个领域有独立的后果（钱、政策、课堂）；
2. 这一句能给出一个新的数字、一个新的承担者，或者一个新的时间尺度。

副视角写成一句话，不单独成段，不重复主视角已经说过的话；如果另一份日报同期也写了同一件事，副视角就压到一句话，不展开。

**分两级写。**

- **头条（每期第一张卡片）**：副视角可以展开成 2–3 句，写清另一个领域关心的数字与结论。写在同一段 `<p class="why">` 里，用 `<b>另一个视角</b>` 起头，需要换行用 `<br>`；**不要新开第二个 `<p class="why">`**，解析器只认第一个，多出来的会被当成正文段落。
- **其余卡片**：仍然只写一句话，不加标签。

例（头条）：`<p class="why"><b>看点</b>……（工程师视角）<br><b>另一个视角</b>……（经济学家的两句话）</p>`

例（经济日报写 Anthropic 招股书）：主视角是经济学家——8954 亿美元的承诺排到 2045 年、12 个月内到期 698 亿，这是一张类债务的长期负债表；末尾一句工程师的——合同锁定了未来算力，训练规模的上限由合同而不是技术决定。


## 5. 写中英两版

中文：`daily-economy/$DATE.html`
英文：`daily-economy/$DATE-en.html`

- 期号：在最近一期基础上 +1（中文「第 00X 期」，英文「Issue 00X」）。
- 日期、星期、窗口、条数、阅读时长两边一致。
- **英文是重写，不是翻译。** 标题、导语、速览、看点这四处必须重新组织句子；数字、机构名、公司名、法案名要准确。
- 中文用标准中文；英文用标准英文，不要逐句直译。

结构照抄最近一期（masthead / tldr / chapter / card / footer），只换内容。栏目色已经写进 `style.css`，不要在页面里加 `<style>`。

## 6. 发布

```bash
cd /opt/kaixinguor/site
node scripts/publish-economy.mjs "daily-economy/$DATE.html" \
  --en "daily-economy/$DATE-en.html" \
  --push
```

脚本会：

- 生成 `daily-economy/$DATE.html` 和 `daily-economy/$DATE-en.html`；
- 重新生成 `economy.html` 的今日区与往期抽屉、`feed-economy.xml`、`feed-economy-en.xml`、`sitemap.xml`；
- **去重检查默认开启**：发布前先跑 `coverage.mjs check`。同一版块的往期重复、窗口重叠会直接拒绝落盘；同一天另一个版块的重叠只提示不拦，确认侧重点不同即可。追更要按第 2.3 节标记，只有排障才用 `--allow-overlap`。
- **链接检查默认开启**，非 2xx 直接失败、不落盘；失败就删掉那几条重发。

### 6.1 配图：不再生成

**从 2026-11-02 起，经济日报不再出公众号配图（贴图）。** 公众号只发 AI 日报；经济日报只发站内 HTML（中英双语）和 RSS。

- 不要对 `daily-economy/` 跑 `make-social.mjs`；脚本会直接拒绝。
- 已有期数的配图（`daily-economy/social/`）保留原样，不删、不提交、不部署。
- 原因：公众号读者主要来自 AI/教育方向，经济日报的打开率很低，且和账号主线不一致；继续出图只是增加维护成本。

发布后看一眼：

```bash
curl -sS -o /dev/null -w '%{http_code}\n' "https://kaixinguor.com/daily-economy/$DATE.html"
curl -sS -o /dev/null -w '%{http_code}\n' "https://kaixinguor.com/economy.html"
```

## 7. 通知

成功：

```bash
KAIXINGUOR_NOTIFY_NAME="经济日报" /opt/kaixinguor/bin/notify.sh success \
  "经济日报 $DATE 已发布 · N 条 · https://kaixinguor.com/economy.html"
```

失败：

```bash
KAIXINGUOR_NOTIFY_NAME="经济日报" /opt/kaixinguor/bin/notify.sh failure \
  "经济日报 $DATE 生成失败：<一句话原因>。详见 journalctl -u kaixinguor-dsh -n 120"
```

当天不够 4 条、主动不发时，用 `info` 而不是 `failure`。

通知失败不能反过来让任务失败；`notify.sh` 内部已经兜底。

## 8. 纪律

- **打不开的来源一律不收录，宁可少发一条，也不凭标题、摘要或记忆补写。**
- **不和当天的 AI 日报重复做头条。**
- 数字以原文为准；换算、四舍五入、同比环比要说清楚口径。
- 只改日报相关文件；不要改 `style.css`、工具页、隐私页。
- 不要 `git push --force`，不要重写历史。
- 不要提交密钥、token、`.env`。
- 已发布的某条事后发现原文失效：换一条能打开的原始来源，或者下架该条。
- **只发站内（HTML + RSS），不再出公众号贴图**；不要对经济日报跑 `make-social.mjs`。
- 如果当天确实没有足够合格的经济新闻，宁可不发，也不要编。

## 9. 发布前自检（逐条过）

- [ ] 每条都有可打开的原文链接，且我打开过
- [ ] 每条点开都能在十秒内看到标题、发布时间、那组数字
- [ ] 有一级来源的，链接给了一级；只覆盖部分事实的，正文补了行内来源
- [ ] 脚本报「读不到标题」的，已换源或补镜像，没有硬留
- [ ] 没有三级来源（转载、聚合、快讯汇编）当出处
- [ ] 每次说「数据显示」之前，问过这是不是「某机构测算」
- [ ] 每条正文里至少有 2 个具体数字
- [ ] 看点里没有复述事实，没有「值得关注」
- [ ] 头条是当天最能量化的那条，不是最好写的那条
- [ ] 和今天 AI 日报的头条不重复
- [ ] 中英文的标题、导语、速览、看点都是各自重写的
- [ ] `publish-economy` 的链接检查全绿

## 10. 更正

规则同 `每日生成任务.md` 第 9 节，这里只记格式：

- 链接失效 → 换源重发，不发更正；
- 数字错 / 事实不成立 → 在 `issue-footer` 的声明**之前**加一段，写清改了什么、依据什么、什么时候改的：

```html
<p class="correction"><b>更正</b> 10 月 30 日：本条第 2 段的「XX」应为「YY」，依据原文已改。（10/31）</p>
```

不要静默改。读的人要能看到改动痕迹。
