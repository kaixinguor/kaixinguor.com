# 微信「贴图」自动建草稿：可行性研究

> 2026-11-01。结论先行：官方确实有「图片消息（newspic）」草稿接口，可以做到“自动建草稿、人工审完点发布”；但**你这个个人主体、未认证的公众号已经实测调不通**——`draft/count` 和 `material/add_material` 都返回 `48001 api unauthorized`。贴图不是新接口，只是「图片消息」在后台改了名。想走官方 API，只有换主体并认证；否则保持手动，或接受第三方/浏览器方案的风险。

## 0. 一句话回答

| 账号类型 | 能否自动建草稿 | 说明 |
|---|---|---|
| 已认证公众号 / 服务号 | **能**（按文档与权限表） | `draft/add` + `article_type: "newspic"`，草稿进后台草稿箱，人工发表 |
| 个人主体、未认证公众号 | **不能（已实测）** | 2025-07 起发布/群发接口被回收；2026-11-01 实测 `draft/count`、`material/add_material` 均 `48001` |
| 企业主体、未认证 | **大概率不能** | 同上，发布接口明确被回收；草稿接口文档没写死，需实测 |
| 个人主体但已做主体迁移 + 认证 | **能** | 变成“认证公众号”，按认证号走 |

**关键区别：**

- **发布接口**（`freepublish/*`、群发）——个人主体/未认证号**确定没有**。官方 2025-07 的回收说明写得很清楚。
- **草稿接口**（`draft/*`、`material/*`）——官方文档**没有**写“个人主体不可用”，但社区和本号实测都返回 `48001`。2026-11-01 本号实测：`stable_token` 成功，`draft/count` 和 `material/add_material?type=image` 均 `48001`，第一张图就没传上去，草稿也没建出来。

## 1. 官方到底支持什么

### 1.1 完整链路（只建草稿，不发布）

| 步骤 | 接口 | 作用 | 关键限制 |
|---|---|---|---|
| 1 | `POST /cgi-bin/stable_token` | 换 `access_token` | 需要 AppID/AppSecret；调用 IP 必须在白名单 |
| 2 | `POST /cgi-bin/material/add_material?type=image` | 把 5 张图传成**永久素材**，拿 `media_id` | 单图 ≤10MB；支持 png/jpeg/jpg/gif/bmp |
| 3 | `POST /cgi-bin/draft/add` | 建「图片消息」草稿 | `article_type: "newspic"`；`image_info.image_list` 1–20 张；首图即封面 |
| 4 | `POST /cgi-bin/draft/batchget` / `draft/get` | 回读草稿列表/详情 | 用于确认草稿真的建出来了 |
| 5 | 人工 | 后台草稿箱 → 预览 → 发表/群发 | **不在 API 里**，正是你要的“我审完点发布” |

`draft/add` 的 `newspic` 参数边界（官方文档）：

- `title`：必填，≤32 字；
- `content`：必填，图片消息**仅支持纯文本**和少量特殊标签（如商品），**不支持 HTML、外链**；≤2 万字符且 <1MB；
- `image_info.image_list`：1–20 张，每张必须是**永久素材**的 `media_id`；
- `cover_info.crop_percent_list`：可选，图片消息支持 `1_1`、`16_9`、`2.35_1` 三种封面裁切比例——这正好能解决你们文档里“封面会被裁”的坑，可以在建草稿时就把裁切框写死；
- 草稿被群发或发布后，会自动从草稿箱移除。

### 1.2 发布接口（你不需要，但要知道它为什么不行）

`freepublish/submit` 可以把草稿直接提交发布，但官方[发布能力](https://developers.weixin.qq.com/doc/subscription/guide/product/publish.html)页面明确写着：

> 2025 年 7 月起，个人主体账号、企业主体未认证账号及不支持认证的账号将被回收以上接口的调用权限。

所以“自动发布”对个人号是死路；“自动建草稿 + 人工点发布”是另一条路，理论上不碰 `freepublish`，只碰 `draft`。

## 2. 「贴图」和「图片消息」是什么关系

- 2026 年公众号后台把原来的「图片消息」入口改名为「**贴图**」；有媒体称微信在灰度「贴图号」，定位是“只能发贴图的公众号”，入口在公众号后台、公众号助手 App、微信内“我的-作品”。
- 接口世界没有跟着改名：草稿接口里仍然叫 `article_type: "newspic"`，没有单独的“贴图 API”。所以**不要等“贴图专属接口”**，能用的就是 `newspic` 草稿。
- 贴图发布时的「合集」「话题」「公开推荐」「位置」等设置，**API 不能预设**；草稿建好后，仍要在发布前人工选。也就是说，即使草稿自动建好，你的“审完直接点发布”可能还要多点两下（选合集/公开推荐），不是严格的一键。
- API 建出来的草稿，官方只承诺“可在公众平台官网-草稿箱中查看和管理”。微信内“贴图/作品”入口是否同步显示这份草稿，没有官方说明，需要实测；稳妥的审稿入口是**公众号后台草稿箱**或**公众号助手 App 的草稿**。
- 草稿箱里大概率显示为「图片消息」而不是「贴图」——这是同一条内容形态的两个名字，不要以为建错了。

> 参考：白杨SEO《公众号贴图号是什么、入口、怎么上推荐和搜索？》（2026-10-13）把“贴图”定义为原图片/文字功能改名；大众新闻（2026-02-13）报道“贴图号源于原来的图片消息”。

## 3. 你的账号为什么卡住

1. **个人主体不能微信认证。** 腾讯客服明确：个人主体类型公众号/服务号不支持申请微信认证；只有企业/个体户、政府、媒体等组织主体可以。所以“个人号去认证一下”这条路不存在，只能**换主体**（迁移）。
2. **发布/群发接口 2025-07 已回收。** 个人主体、企业未认证、不支持认证的账号都没有 `freepublish/*` 和群发权限。这解释了为什么现在只能手动发。
3. **草稿接口没有明文回收，但实测常 `48001`。** 微信开放社区 2026-02 的帖子：个人公众号调用 `/cgi-bin/draft/add` 返回 `48001 api unauthorized`，开发者平台却显示“有权限”；发帖人还提到 135 等第三方工具授权后可以自动同步到草稿箱。
4. **权限页可能“骗人”。** 接口权限表按账号类型给勾，未必校验认证状态；实际网关仍可能拒绝。所以**唯一判据是你自己的 AppID 调一次**，不是文档，也不是权限页的勾。

### 3.1 本号实测记录（2026-11-01）

用 `~/.env` 里的 `WECHAT_APPID` / `WECHAT_APPSECRET`：

| 步骤 | 结果 |
|---|---|
| `POST /cgi-bin/stable_token` | **成功**（说明 AppID/AppSecret 正确，token 能拿到） |
| `GET /cgi-bin/draft/count` | `{"errcode":48001,"errmsg":"api unauthorized ..."}` |
| `POST /cgi-bin/material/add_material?type=image`（5 张里的第 1 张） | `48001 api unauthorized`，**没有上传成功** |
| `POST /cgi-bin/draft/add` | 没走到（素材就失败了），**没有建出草稿** |

结论：不是 token 问题，不是 IP 白名单问题，是**这个账号没有素材/草稿接口权限**。后台草稿箱里不会多出测试草稿，不用去删。

> 注意：以上结论只对 `~/.env` 里这个 AppID 有效。如果它不是日报所用的那个公众号，换正确的 AppID/AppSecret 再复测一次。

> 排障插曲：`~/.env` 的 `WECHAT_APPID` 行尾有一个空格，脚本原来不 `trim()`，第一次调用返回 `40013 invalid appid`。已修 `scripts/wechat-draft.mjs`：读 `.env` 和读环境变量都做 `trim()`；顺带补了 `40013` / `40125` 的错误提示。所以上面的 `48001` 是真实的权限错误，不是配置错误。

## 4. 五条路，怎么选

| 路径 | 能否自动建草稿 | 成本 | 风险/限制 | 建议 |
|---|---|---|---|---|
| **A. 现账号直接调 API** | **实测不能（48001）** | 0 | 素材/草稿接口均未授权 | **不用再试**；除非换主体 |
| **B. 换主体 + 微信认证** | 能 | 迁移审核 300 元 + 公证 1–2 天 + 认证 300 元/年 | 迁移要求双方主体验证、异主体公证；迁全部粉丝要求目标号粉丝 ≤1000；周期约 1–2 周 | 长期做公众号，选这条 |
| **C. 第三方授权（135/壹伴等）** | 可能能同步草稿 | 工具会员费 | 依赖第三方；自动化程度低；政策/接口随时变；数据经过第三方 | 只适合手动辅助，不适合每日自动 |
| **D. 浏览器自动化（Chrome 登录态/CDP）** | 技术能做到 | 一台常开机器 | 扫码登录会过期；异地/自动化风控；页面改版就挂；有封号风险 | **不推荐**，省 2 分钟不值 |
| **E. 保持手动** | 不能 | 0 | 每天 2–3 分钟 | 最稳；先把文案和图片顺序做到“闭眼拖” |

### 关于 B（迁移 + 认证）的现实数字

- 账号迁移：异主体需在公证机关做申请公函印鉴公证，审核费 300 元；审核 1–3 个工作日，迁移 1–3 天；迁移后原号回收，目标号承接粉丝/文章素材等。
- 迁移全部关注用户时，目标账号粉丝数必须 ≤1000；超过 1000 只能选择不迁全部粉丝。
- 微信认证：300 元/次/年；个体工商户认证**不需要对公账户**，企业需要。
- 也就是说，最低成本大约是 **300（迁移）+ 300/年（认证）+ 公证费/时间**。如果只是为了每天省 2 分钟，不划算；如果公众号是长期分发渠道，这笔钱比“浏览器自动化封号”便宜。

### 关于 C（第三方）的边界

社区有用户反馈 135 等第三方授权后可以同步到草稿箱，但这不代表你能把它接进每日自动流程：

- 第三方的“同步”通常是**手动点一下**，不是给你 API；
- 即使有定时/自动同步，也依赖第三方的授权和策略，且内容要经过第三方服务器；
- 个人号在第三方那边能否稳定授权，也可能随微信政策变化。

所以 C 只能算“比手动省几步”，不是“自动建草稿”的工程方案。

### 关于 D（浏览器自动化）为什么不做

技术上完全可行：用持久化 Chrome profile 登录公众号后台，CDP 上传图片、填标题正文、点“保存草稿”。但：

- 公众号后台登录态会过期，需要人工扫码；无人值守时一过期就断；
- 微信对异地登录、自动化操作有风控，轻则验证，重则限制；
- 后台 DOM 一改版，脚本就废；
- 你们的 `docs/每日生成任务.md` 已经写了“不要试图用扫码登录态脚本自动化”，这条纪律是对的。

## 5. 如果换主体后探测通过：改造方案

现有 `scripts/wechat-draft.mjs` 已经写好了 80%，它做的正是：

```
stable_token → material/add_material ×5 → draft/add (newspic) → 打印 media_id
```

要把它接进每日流程，建议补四件事：

1. **幂等**：把 `draft media_id` 写进 `manifest.json`（例如 `wechatDraftMediaId`）。重跑时先 `draft/get`：
   - 草稿还在 → `draft/update` 或直接跳过；
   - 草稿已被发布/删除 → 才新建；
   - 请求超时/断线 → **不要自动重试**，先让人去草稿箱确认，避免一天建出两篇。
2. **封面裁切**：建草稿时传 `cover_info.crop_percent_list`，至少给 `1_1` 和 `16_9` 两组，按你们封面主标题的位置算好 x1/y1/x2/y2，解决“信息流里封面被裁”。
3. **错误分诊**：
   - `40164` / `61004`：调用 IP 不在白名单 → 去微信开发者平台加 IP；
   - `48001`：账号无权限 → 不要再重试，直接降级为手动；
   - `89503`：需要管理员在手机上确认本次调用；
   - 超时/网络错误：结果不确定，先查草稿箱再决定，不自动重发。
4. **通知**：成功发“草稿已建，去草稿箱审”；失败发“无权限/需手动”，并把 5 张图和文案路径带上。不要因为草稿失败影响日报上线。

人工审稿路径：

```
mp.weixin.qq.com → 内容与互动 → 草稿箱 → 图片消息
→ 预览（看封面裁切、字号）
→ 选合集/话题/公开推荐
→ 发表（生成链接、不推送）或 群发（推送粉丝，个人号 1 天 1 次）
```

**不要**接 `freepublish/submit`：你只要草稿，发布权留在人手里。

## 6. 探测结果与复测方法（2026-11-01）

### 6.0 本次结果：不通过

| 调用 | 结果 |
|---|---|
| `stable_token` | 成功 |
| `draft/count` | `48001 api unauthorized` |
| `material/add_material?type=image` | `48001 api unauthorized`（第 1 张图就失败） |
| `draft/add` | 未执行（素材失败），没有草稿产生 |

**现账号的官方 API 路径已经判死。** 下面的 6.1–6.4 保留给“换主体/换号后复测”，不用在当前号上重复跑。

### 6.1 先看权限页（只能参考，不能定论）

微信开发者平台 → 我的业务 → 公众号 → 接口管理 → 接口权限与额度，看“草稿/素材”相关接口是否在列表里。**注意：权限页打勾也可能实际 `48001`**，所以还要跑 6.2。

### 6.2 只读调用（复测用）

在 `site/` 下，用 `~/.env` 里的 `WECHAT_APPID` / `WECHAT_APPSECRET`（不要打印 secret）：

```bash
cd site
set -a; source ~/.env; set +a

TOKEN=$(curl -sS -X POST "https://api.weixin.qq.com/cgi-bin/stable_token" \
  -H 'content-type: application/json' \
  -d "{\"grant_type\":\"client_credential\",\"appid\":\"$WECHAT_APPID\",\"secret\":\"$WECHAT_APPSECRET\",\"force_refresh\":false}" \
  | jq -r '.access_token // empty')

echo "token: ${TOKEN:+ok}"

curl -sS "https://api.weixin.qq.com/cgi-bin/draft/count?access_token=$TOKEN" | jq .
```

这一步只取 token、查草稿总数，**不建草稿、不上传图片**。

### 6.3 结果判读

| 返回 | 含义 | 下一步 |
|---|---|---|
| `{"total_count":N}` / `errcode:0` | 草稿读取接口可用（强信号，不等于 `add` 一定可用） | 再建一篇测试草稿确认 `newspic` 全链路 |
| `48001 api unauthorized` | 无权限（个人未认证常见；**本号 2026-11-01 即此结果**） | 官方 API 这条路判死；走 B/C/E |
| `40164` / `61004` | IP 不在白名单 | 开发者平台加当前出口 IP，再试 |
| `89503` | 需要管理员确认 | 让管理员在手机上确认本次调用，再试 |
| `40013` / `40125` | AppID / AppSecret 不正确 | 检查是否带空格、是否拿成了别的账号 |
| 其它 | 按 errmsg 排查 | 把完整 errcode/errmsg 发我 |

### 6.4 如果复测通过：建一篇测试草稿

用当天现成的 manifest 跑：

```bash
node scripts/wechat-draft.mjs daily-ai/social/2026-11-01/manifest.json --dry-run   # 先只校验本地文件
node scripts/wechat-draft.mjs daily-ai/social/2026-11-01/manifest.json             # 真建草稿
```

然后去后台草稿箱看：标题、描述、5 张图顺序、封面裁切、能否打开编辑、能否点发表。确认无误后，这篇就是当天的正式草稿；如果只是测试，删掉即可。

## 7. 建议

1. **现账号不要再试官方 API。** 2026-11-01 已实测 `48001`，所有代码工作都是白做；除非换主体/换号。
2. **如果只是每天省 2 分钟**：保持手动，把 `公众号-图片消息.md` 的步骤再压缩（图序、标题、描述都现成），不值得为它迁主体或冒封号风险。
3. **如果公众号是长期渠道**：把主体迁到个体户/企业并认证，走官方 `draft/add`；以后想自动发布也有 `freepublish` 可用（但仍建议保留人工审）。
4. **不要等“贴图 API”**：贴图就是 `newspic`，没有新接口。
5. **不要用浏览器自动化代登录**：这是唯一可能“今天能跑、明天封号”的方案。
