# 自动化与部署

> 目标：日报更新一次，GitHub 上看到一次，站点自动更新；不需要手动上传文件，也不需要维护服务器。

---

## 0. 先看整条链路

```
DeepSeek Harness 生成同一期的中文版 + 英文版 HTML
        │
        ▼
node scripts/publish-daily.mjs <中文.html> --en <英文.html> --check-links --push
        │  ① 解析两版  ② 分别套壳写入 daily/YYYY-MM-DD.html 与 -en.html
        │  ③ 重生成首页双语全文/抽屉/两份 RSS/sitemap
        │  ④ 检查原文链接  ⑤ commit + push
        ▼
GitHub · main
        │
        ▼
Cloudflare Pages / Workers（推荐 Pages 连 GitHub）
        │
        ▼
kaixinguor.com  +  feed.xml / feed-en.xml（中英文 RSS）
```

**结论先说：静态站点不需要「服务器」也能自动更新。** 最省事、最稳的技术组合是：

- 内容：中英双语的静态 HTML（Node 脚本生成，无数据库、无 CMS）
- 源码：GitHub
- 构建/部署：Cloudflare Pages 连 GitHub（push 即上线）
- 通知：RSS（`/feed.xml` 中文、`/feed-en.xml` 英文），想更主动可以再加邮件/Telegram
- 自有服务器只在「域名备案 + 国内访问」必须时才需要，优先级放在最后

## 1. 发布一期日报

### 1.1 生成

在 DeepSeek Harness 的日报任务里，生成**同一期的两版 HTML**：

- 中文版：`ai-daily/2026-10-26.html`
- 英文版：`ai-daily/2026-10-26-en.html`

两版都用同一套结构（`.masthead` / `.tldr` / `.section.chapter` / `.card` / `.why` / issue `<footer>`），脚本分别解析后套上站点外壳。版式只维护一份（`style.css` + `templates/issue.html`），语言只影响文案。

英文版必须是**标准英语重写**，不是逐字直译。具体见 1.5。

### 1.2 发布（本地）

```bash
cd site

# 先看解析结果，不写文件
node scripts/publish-daily.mjs ../ai-daily/2026-10-26.html \
  --en ../ai-daily/2026-10-26-en.html --dry-run

# 正式写入 daily/，并重生成首页全文、往期抽屉、两份 RSS、sitemap
node scripts/publish-daily.mjs ../ai-daily/2026-10-26.html \
  --en ../ai-daily/2026-10-26-en.html

# 更稳妥：逐条检查原文链接，全部 200 才写入
node scripts/publish-daily.mjs ../ai-daily/2026-10-26.html \
  --en ../ai-daily/2026-10-26-en.html --check-links

# 发布 + 提交 + 推送（GitHub 那边就看到更新了）
node scripts/publish-daily.mjs ../ai-daily/2026-10-26.html \
  --en ../ai-daily/2026-10-26-en.html --check-links --push
```

参数：

| 参数 | 作用 |
|---|---|
| `--en <file>` | 英文版 HTML；不写就找同目录的 `YYYY-MM-DD-en.html` |
| `--check-links` | 用浏览器 UA 逐条请求原文，非 2xx 直接失败，不写入 |
| `--allow-bad-links` | 链接检查失败也继续（只打印警告） |
| `--push` | `git add daily/ index.html feed.xml feed-en.xml sitemap.xml` → commit → `git push origin <当前分支>` |
| `--dry-run` | 只解析、打印，不写文件 |

`--push` 只提交这一期相关的产物，不会把工作区里别的改动一起带走。其它改动请自己单独 commit。

**幂等**：同一天重跑会覆盖 `daily/2026-10-26.html`，不会追加，也不会产生重复期号。生成失败时保留上一版。

### 1.3 脚本到底改了什么

```
daily/2026-10-26.html       新增/覆盖（中文）
daily/2026-10-26-en.html    新增/覆盖（英文）
index.html                  TODAY_ZH / TODAY_EN / ARCHIVE_SIDEBAR_ZH / ARCHIVE_SIDEBAR_EN
feed.xml                    重新生成（中文 RSS 2.0）
feed-en.xml                 重新生成（英文 RSS 2.0）
sitemap.xml                 重新生成（含中英文往期）
```

首页是「带标记的静态页」，不是全量模板；这样想手改某一块时不会被下次构建冲掉，只改标记之间的内容即可。首页直接放整份日报，并根据 `<html lang>` 只显示中文或英文其中一版，不会上下堆叠；往期抽屉同理。`archive.html` 只保留一个旧链接跳转（`/#archive`），不再单独维护。

### 1.4 每日任务里怎么接

在日报生成任务的最后一步加一句（把日期替换成当天）：

```text
生成完成后，分别保存中文版和英文版：
  ai-daily/YYYY-MM-DD.html
  ai-daily/YYYY-MM-DD-en.html
然后 cd /Users/or/Documents/deepseek-harness/kaixinguor-workspace/site
执行 node scripts/publish-daily.mjs ../ai-daily/YYYY-MM-DD.html \
  --en ../ai-daily/YYYY-MM-DD-en.html --check-links --push
英文版必须是标准英语重写，不是逐字直译。
如果链接检查失败，换可用来源；换不到就删掉那条再重跑。
```

这样「不定时更新」就变成了：**日报什么时候生成完，什么时候推送上线**，不依赖固定 cron。

### 1.5 中英文版的写作标准

这不是「把中文逐字翻成英文」，而是同一份事实的两种标准写法。

**英文版**

- 用标准新闻英语重写标题、导语、速览、摘要和「Why it matters」，不要保留中文语序。
- 标题短、主动语态；摘要先给事实，再给数字或影响。
- 统一术语：`Models & Capabilities`、`Products & Agents`、`Research & Safety`、`Embodied AI`、`Industry & Capital`；`Why it matters`。
- 日期写 `October 26, 2026`；窗口写 `Oct 25, 11:56 – Oct 26, 11:56 (UTC+8)`；`9 items`；`6 min read`。
- 来源名用惯用英文名：`Synced`（机器之心）、`Xinzhiyuan`（新智元）、`National Business Daily`（每日经济新闻）、`City Express`（都市快报）、`Securities Times`（证券时报）、`Cailian Press`（财联社）、`ET Net`（經濟通）。
- 公司名用官方英文名：`AgiBot`、`Infinigence AI`、`Three-Body Universe`、`Moonshot AI`、`MiniMax`、`Zhipu` 等。
- 数字、引语、归因、链接必须与中文版一致；不要新增未核实的事实。
- 英文里不要出现中文标点；引号用英文引号，破折号前后不加空格。
- 期脚注保留 `Disclaimer`：由 AI agent 搜索、整理并总结，条目均链接原文，事实与数字以原文为准，仅供参考。

**中文版**

- 用标准现代汉语，不要英文直译腔；术语前后一致。
- 标题短、信息密度高；摘要先事实后判断。
- 数字、来源、链接与英文版对齐。

**发布前扫一遍**

- [ ] 两版的日期、期号、条数、窗口一致
- [ ] 英文没有中文标点、没有逐字直译的句子
- [ ] 所有原文链接两版共用，且能打开
- [ ] 首页中英文全文、往期抽屉、两份 RSS 都指向对应语言页面

## 2. 三种自动更新方式

### 方案 A（推荐）：Cloudflare Pages + GitHub

零服务器、零 cron、全球 CDN、免费额度足够。站点是纯静态文件，正好适配。

1. GitHub 仓库：`kaixinguor/kaixinguor.com`
2. Cloudflare Dashboard → Workers & Pages → 创建 Pages 项目 → 连接 GitHub 仓库
3. 构建设置：
   - Framework preset：`None`
   - Build command：`node scripts/stage.mjs`
   - Build output directory：`dist/site`
   - 环境变量：`NODE_VERSION=20`
4. 保存并部署。以后只要 `git push` 到 `main`，Pages 自动构建 → 上线。
5. 自定义域 `kaixinguor.com` 指到这个 Pages 项目。

**触发方式**：`git push`。不需要在服务器上做任何事。

> 为什么用 `node scripts/stage.mjs` 而不是直接输出根目录？
> 因为仓库里还有 `scripts/`、`docs/`、`deploy/`、`templates/` 这些开发文件。`stage.mjs` 只把公开文件拷到 `dist/site/`，不会把内部笔记和脚本传上去。

### 方案 B：GitHub Actions + Wrangler 部署

适合想在一个地方做「构建校验 + 部署 + 密钥管理」的情况。仓库里已经带了一份：

`.github/workflows/deploy.yml`

默认只做 `build & check`，部署 job 是关的。要启用：

1. Settings → Secrets and variables → Actions
2. New repository secret：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`
3. New repository variable：`CF_PAGES_DEPLOY` = `true`
4. 推送 `main`，Actions 会：
   - `node scripts/build.mjs --check`（生成文件是否最新）
   - `node scripts/stage.mjs`
   - `wrangler pages deploy dist/site --project-name=kaixinguor`

**不要和方案 A 同时开**，否则同一次 push 会部署两遍。二选一。

> 如果你用的是 Cloudflare **Workers Static Assets**（仓库里的 `wrangler.jsonc`），本地也可以：
> `npm run build && npm run stage && npx wrangler deploy`
> `wrangler.jsonc` 的 `assets.directory` 指向仓库根目录，`.assetsignore` 已经把开发文件排除。

### 方案 C：自有服务器（阿里云 / 宝塔 / ECS）

只有这两种情况才建议：

- 域名要备案、主要访问在国内，Cloudflare 的线路不理想
- 你已经有服务器，想复用它

**推荐做法：GitHub Actions 构建后用 rsync 推到服务器**，服务器上不用装 Node，也不用跑构建。

```yaml
# 追加到 .github/workflows/deploy.yml 的一个 job（示意）
- name: Build
  run: |
    node scripts/build.mjs
    node scripts/stage.mjs
- name: Rsync to server
  run: |
    rsync -az --delete dist/site/ \
      user@your-server:/www/wwwroot/kaixinguor/
  env:
    SSH_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
```

配合 `appleboy/ssh-action` 或 `rsync` + SSH key 均可。触发仍然是 `git push`。

**更简单的替代：服务器 cron 拉取**

```bash
# /etc/cron.d/kaixinguor  (每 5 分钟)
*/5 * * * * root cd /opt/kaixinguor-src && git pull --ff-only && node scripts/stage.mjs && rsync -a --delete dist/site/ /www/wwwroot/kaixinguor/
```

- 优点：不需要 GitHub Actions 的 SSH 密钥
- 缺点：服务器要装 Node 20+；最多延迟 5 分钟；`git pull` 失败要能发现（日志/告警）

**不建议**用「GitHub webhook → 服务器 PHP 接口」：为了省 5 分钟延迟，多维护一个公网入口和一套鉴权，不划算。

### 方案 D：完全无人值守（不打开 DSH）

当前日报是 DeepSeek Harness 在会话里生成的。如果希望「机器自己每天生成」，需要把生成也搬到无人值守环境：

- 一个定时任务（GitHub Actions cron 或服务器 cron）
- 一个能联网检索 + 调用大模型的脚本（模型 API Key、搜索 API Key）
- 生成 → 发布脚本 → 部署

这比「部署」复杂得多，而且链接校验、版式稳定性、失败重试都要自己兜。建议先把 A 跑顺，再考虑 D。GitHub Actions 的 cron 有两个坑：

- 时间是 **UTC**：北京 9:00 = `0 1 * * *`
- 仓库 60 天无提交，定时工作流会被自动停用

## 3. 上线检查清单

```bash
cd site

npm run build          # 生成首页双语全文/抽屉/两份 RSS/sitemap
npm run check          # 检查生成文件是否最新（CI 也跑这个）
npm run check:links    # 检查最新一期中英文页面的所有原文链接
npm run stage          # 生成 dist/site/
```

浏览器里看：

- [ ] 1280 宽：首页（完整日报 + 贴边往期抽屉）、中文日报、英文日报、工具、许愿
- [ ] 390 宽：单栏不横向溢出
- [ ] 深色 / 浅色都能读
- [ ] 工具页标签能筛：全部 / 听课 / 阅读 / 许愿
- [ ] 日报目录锚点能跳
- [ ] `/feed.xml` 和 `/feed-en.xml` 都是合法 RSS
- [ ] 随便一个不存在的地址返回自己的 `404.html`
- [ ] `curl -I` 看 HTML 是 `no-cache`，静态资源有缓存
