# 每日生成任务（给定时 Agent 的作业说明）

> 这是每天 09:00（Asia/Shanghai）定时任务要执行的内容。  
> 工作目录：`/opt/kaixinguor/site`（仓库根目录），`ai-daily/` 在它的上一级：`/opt/kaixinguor/ai-daily/`。

## 0. 先做幂等检查

```bash
cd /opt/kaixinguor/site
TZ=Asia/Shanghai date '+%F %T %Z'
git pull --ff-only

# 如果这是“补跑昨天 9 点”的提醒，但现在是今天 9 点前：
# 不要提前生成今天的日报，等今天 9 点的正常触发。
NOW="$(TZ=Asia/Shanghai date +%H%M)"
if [ "$NOW" -lt 0900 ]; then
  /opt/kaixinguor/bin/notify.sh info "AI 日报：当前早于 09:00，跳过补跑，等待今天 09:00"
  exit 0
fi
```

如果执行到上面的 `exit 0`，这次任务就到此结束，不要再做任何生成。

设：

```bash
DATE="$(TZ=Asia/Shanghai date +%F)"
```

如果 `daily-ai/$DATE.html` 和 `daily-ai/$DATE-en.html` 都已经存在，而且不是空的：

- 不要重复生成、不要重复提交；
- 运行 `notify.sh success "AI 日报 $DATE 已存在，跳过重复生成"`；
- 结束。

## 1. 时间窗口

- 以当前时刻 `T` 为终点，严格回看 24 小时：`[T-24h, T]`。
- 只收**发布时间**落在这个窗口内的报道。
- 页面上没有 `publishedAt` 时，打开原文确认；无法确认就放弃，不要用“最近看到”代替。
- 不把前一天的旧闻重新包装；不在窗口内的新闻一律不收。

## 2. 检索与核验

至少做 3 轮、累计 10 个以上不同角度的查询，例如：

- 英文：`AI news <date>`、`model release <date>`、`AI safety <date>`、`AI funding <date>`、`embodied AI <date>`；
- 中文：`大模型 <date>`、`AI 融资 <date>`、`具身智能 <date>`、`AI 安全 <date>`；
- 针对已发现线索再做公司名/产品名/事件名的二次搜索。

每条候选都要：

1. **先打开原文，再决定收不收。** 打不开的一律不收录——包括 403 / 反爬、登录墙、付费墙、Cloudflare 验证页、返回 200 但其实是“页面不存在”的软 404、只有搜索摘要或转载片段而原文进不去的情况。
2. 打不开就**整条删掉**，不要用“另一家的转载”顶替、不要凭标题和搜索摘要补写正文、不要猜数字。换一条能打开的来源，换不到就少发一条。
3. 打开后逐条核对：**标题、发布时间、正文首段**是否与你要写的那件事一致。链接检查只能证明“能打开”，证明不了“是你引用的那一篇”——有的站会把失效链接悄悄跳到首页或另一篇文章。
4. 记录**时间（MM/DD HH:MM，北京时间）**、来源名、原文链接。
5. 事实、数字、引语以原文为准；标题和点评可以做编辑加工，但不能改变事实。
6. 优先原始来源（公司博客、官方发布、监管文件、主流通讯社/媒体）；只有二传来源时，在正文里写清楚“据……报道”。
7. 链接发布前会由脚本逐条请求（浏览器 UA，默认开启），返回非 2xx 直接拦住、不落盘。

## 3. 选条与结构

- 总共 **6–9 条**，建议 9 条。
- 按五个栏目组织，尽量每个栏目都有内容：
  1. 模型与能力（Models）
  2. 产品与智能体（Products）
  3. 研究与安全（Research & Safety）
  4. 具身智能（Embodied AI）
  5. 行业与资本（Industry & Capital）
- 同一事件不要拆成多条；同一公司不要占据超过 2 条。
- 头条选当天最重要的 1 条；TL;DR 3 条，分别覆盖头条、资本/产业、安全/研究。
- 每条卡片必须有：时间、来源名、标题、2–4 段事实、1 段“看点”（为什么重要，不要复述事实）。
- 标题用陈述句，不用“震惊”“炸裂”等词；正文用标准中文，英文版用标准英文，不要逐字直译。

## 4. 写中英文两版

中文：`../ai-daily/$DATE.html`  
英文：`../ai-daily/$DATE-en.html`

以最近一期为结构模板（masthead / tldr / chapter / card / footer），但不要复制旧内容。要点：

- 期号：在最近一期基础上 +1；例如上一期是 `第 002 期` / `Issue 002`，这一期就是 `第 003 期` / `Issue 003`。
- 日期、星期、窗口、条数、阅读时长要一致。
- 中文用“第 00X 期”，英文用“Issue 00X”。
- 页脚保留 AI 声明，不要写“全部落在 24 小时窗口内”这类和窗口重复的话。声明的**固定文案**（逐字照抄，中英文各自一套，不要自创、不要再加“据…报道/未核实”这类补充句）：

  ```html
  <p class="disclaimer"><b>声明</b> 本期内容由 AI Agent 搜索、整理并总结，所有条目均链接原文；事实与数字以原文为准，仅供参考。标题与点评为编辑加工，不代表任何来源立场。</p>
  ```

  配图封面底部和图片消息描述里的声明，脚本会**直接从当天页面抓取**这段文字，不用手写。
- 英文版不是中文版的逐句翻译：公司名、产品名、数字、引语要准确，表达要自然。

## 5. 发布

```bash
cd /opt/kaixinguor/site
node scripts/publish-daily.mjs "../ai-daily/$DATE.html" \
  --en "../ai-daily/$DATE-en.html" \
  --push
```

脚本会：

- 生成 `daily-ai/$DATE.html` 和 `daily-ai/$DATE-en.html`；
- 更新首页整份日报、往期抽屉、`feed.xml`、`feed-en.xml`、`sitemap.xml`；
- 只提交 `daily-ai/ index.html feed.xml feed-en.xml sitemap.xml`；
- **链接检查默认开启**（不再需要 `--check-links`）：逐条用浏览器 UA 请求原文，非 2xx 直接失败、不落盘；返回 200 但标题像 404 / 已删除 / 无权限的，也算失败。失败就删掉那几条，不要带病发布。
- 输出里出现“需要人工确认”的链接（验证页、登录页、读不到标题），说明脚本读不到正文——**你必须自己在浏览器打开看一眼**，确认是本条引用的那篇，再决定留不留。
- 只有排障时才用 `--no-check-links` 跳过检查；正常发布不要用它。

发布后看一眼：

```bash
git log -1 --oneline
curl -sS -o /dev/null -w '%{http_code}\n' "https://kaixinguor.com/daily-ai/$DATE.html"
curl -sS -o /dev/null -w '%{http_code}\n' "https://kaixinguor.com/daily-ai/$DATE-en.html"
```

## 6. 生成公众号图片消息图（本地，不上线）

日报发布后，用当天页面出 **5 张图 + 一份发布文案**：

```bash
cd /opt/kaixinguor/site
node scripts/make-social.mjs "daily-ai/$DATE.html"
# 等价写法：npm run social -- "daily-ai/$DATE.html"
```

产出（默认放在站点仓库外，避免误提交）：

- `../ai-daily/social/$DATE/wechat/01-cover.png … 05-overview.png`：1080×1440（3:4）；
- `../ai-daily/social/$DATE/公众号-图片消息.md`：标题 / 描述 / 逐图说明 / 发布步骤，发布时直接复制；
- 同目录 `AI-Daily-$DATE-wechat.zip`、`README.txt`、`manifest.json`。

规则（完整版见 [`社交配图规则.md`](社交配图规则.md)，不要自行改回去）：

- **只做公众号，不再生成小红书图**；传 `--only xhs` 会直接报错。
- **固定 5 张：封面 → 3 条重点 → 速览，没有尾页。** 重点 = 头条 + 两条最贴近 TL;DR 的新闻，脚本自动匹配，不用手选。
- **标题固定 `AI 日报 · M月D日`**（如 `AI 日报 · 10月30日`）：不写期号、不用当天 headline。脚本已写进 `manifest.json` 的 `wechatTitle` 和文案文件，不要手改。
- AI 免责声明有两份、脚本从当天页面自动抓取（连“声明”两个字一起）：**01 封面底部**一行小字 + **描述正文**末尾。不要再为它单独加一张图，也不要加回速览页（会挤掉最后一条正文），更不要手写这段文字。
- 只生成在本地，不写 `site/`、不提交、不部署；日报正文的发布不受影响。
- 同一天重跑会覆盖；改了 `scripts/social/template.mjs` 后重跑即可。
- 生成失败不要卡住日报发布；成功通知可以补一句“配图已生成”，失败就补“配图未生成”。
- 发布是**手动**的（个人主体订阅号没有发布接口权限）：打开 `mp.weixin.qq.com` → 草稿箱 → 新建 → 图片消息，按文案文件里的顺序拖图。不要试图用扫码登录态脚本自动化。

首次在一台机器上使用要装 Python Playwright 和 Chromium：

```bash
python3 -m pip install playwright
python3 -m playwright install chromium
# Linux 还要中文字体：sudo apt install -y fonts-noto-cjk
```

也可以在发布时一次跑完：给 `publish-daily.mjs` 加 `--social`。

## 7. 通知

成功：

```bash
/opt/kaixinguor/bin/notify.sh success "AI 日报 $DATE 已发布 · N 条 · https://kaixinguor.com/"
```

失败（包括链接检查失败、构建失败、推送失败）：

```bash
/opt/kaixinguor/bin/notify.sh failure "AI 日报 $DATE 生成失败：<一句话原因>。详见 journalctl -u kaixinguor-dsh -n 120"
```

通知失败不能反过来让日报任务失败；`notify.sh` 内部已经兜底。

## 8. 纪律

- 只改日报相关文件；不要改样式、工具页、隐私页。
- 不要 `git push --force`，不要重写历史。
- 不要提交密钥、token、`.env`。
- `../ai-daily/social/` 是本地成品图，不要加进站点仓库。
- 不要为了凑条数收录旧闻、传闻或没有原文链接的内容。
- **打不开的来源一律不收录，宁可少发一条，也不凭标题、摘要或记忆补写。** 没看过的内容不写进日报，这条没有例外。
- 已发布的某条事后发现原文失效：要么换成能打开的原始来源，要么下架该条，不要留着链接指向 404。
- 如果当天确实没有足够合格新闻，宁可少发（6 条）并在通知里说明，也不要编。
