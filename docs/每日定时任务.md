# 每天自动发布四份日报（Ubuntu + DSH）

> **当前状态：已部署（2026-11-26）。** 服务器 `39.107.233.27` 上每天 08:00 由一条 systemd 链路
> 依次跑 AI → 经济 → 教育 → 心理四份日报，每份发布后同步到 nginx；本文就是现在的实现说明。
> 每天 08:00 起按 AI → 经济 → 教育 → 心理 串行跑四份，每份发布后同步到 nginx；本文就是现在的实现说明。
> 目标：08:00 开始，四份**串行**发布（上一份成功才跑下一份），中英双语；服务器关机错过就开机补跑整条链；
> 任何一份失败立即停并推送到手机。
>
> **和 Cloudflare 时代的区别（重要）**：`publish-*.mjs --push` 只推 GitHub，线上不会变。线上是这台 ECS 的
> `/home/project/kaixinguor.com`，由 nginx 直接服务，**没有** GitHub → 服务器的自动同步。
> 所以服务器上的日报任务最后必须多跑一步 `deploy/daily/sync-site.sh`（build + stage + rsync 到 nginx 目录），
> 否则日报提交了、站点还是旧的。
> 架构：**systemd timer + `dsh headless`**（不是 cron，也不是 Web 里的 schedule，理由见下节）。
> 手动一次性触发四份时，按 [每日四报统一规则](每日四报统一规则.md) 执行；自动任务是一条 08:00 起的串行链路。

## 为什么是"一条链路"，而不是四个定时点

实测（2026-11-26，服务器上的 `@deepseek-ai/dsh@0.2.0-rc.2`）：headless profile 带 `web-search-deepseek`、
`web-fetch-http`、`tool-web`、`dsh-skill`，一份日报可以在一个进程里跑完就退出。

**四份不能各定一个时间点并发。** 每份发布都要 `build.mjs`（重写首页、RSS、sitemap）再 `git commit` + `git push`：
四个进程同时做会抢 `.git/index.lock`、互相覆盖构建产物、push 互斥；而且并发时后一份读不到前一份刚发的内容，
跨版块撞题只能靠任务书里的文字约定。

所以是一个 timer + 一条串行链路：

```
08:00 kaixinguor-daily-chain.timer
  └─ kaixinguor-daily-chain.service
       └─ run-chain.sh ai
            ├─ run-daily.sh ai          # 成功才继续；失败就停并通知
            ├─ run-daily.sh economy
            ├─ run-daily.sh education
            └─ run-daily.sh psychology
                 └─ 每份内部：git pull --ff-only → dsh headless →
                    publish（不推送）→ sync-site.sh --no-build →
                    本地 git commit → 文件与线上 200 自验 → notify
       └─ 四份都成功后才统一 git push（重试 8 次），推送结果单独 notify
```

- 上一份成功才跑下一份，**不存在两份同时写仓库**
- 站点优先：每份发完立刻 `sync-site` 上线，四份都落地后才推 GitHub；
  推送失败不影响当天站点，只发一条失败通知，之后手动或下一轮补推
- 任何一份失败：立刻停，后面几份今天不跑，Bark 说明停在哪一份、怎么从那份接着跑
- 顺序固定 AI → 经济 → 教育 → 心理，后一份能读前一份已发布的页面
- `Persistent=true`：错过 08:00（关机）就在开机后补跑整条链
- 单份的 service（`kaixinguor-daily@economy.service` 等）保留，用来手动补跑某一版块

代价说清楚：总耗时是四份之和（实测 AI 一份约 19 分钟，四份大概 60–90 分钟），所以第四份通常在 09:20–10:00
之间落地，不是固定 09:30；任何一份挂了，当天后面的几份默认不发，需要人工从断点续跑。

## 0. 前提

- Ubuntu 22.04 / 24.04，能 sudo；
- 一个能写 `kaixinguor.com` 仓库的 GitHub 账号（建议用 Deploy Key，只给这一个仓库写权限）；
- DeepSeek API Key（DSH 的模型和 web search 都用它）；
- 一个通知通道：Bark / ntfy / 飞书机器人 / Telegram 任选；
- 服务器能访问 `api.deepseek.com`、GitHub、新闻源。

以下命令默认仓库在 `/opt/kaixinguor/site`，运行用户 `kaixinguor`。路径可以换，但服务文件、脚本和文档要一起改。

## 5. 任务书与试跑

四份日报的"任务书"在 `deploy/daily/prompts/{ai,economy,education,psychology}.txt`，
安装到 `/opt/kaixinguor/prompts/`。`run-daily.sh` 把里面的 `__DATE__` 换成当天日期再交给 `dsh headless`。

任务书里写死了这些，改流程就改这里：

- 窗口先跑 `coverage.mjs window`；当天已有文件就沿用记录的 start/end，不按当前时间重算
- 每条必须打开原文核对标题/时间/首段，打不开就换源或删条
- 中英成对、期号 +1、发布前 `parseIssue` / `coverage check` / `check-links` / `style` 全绿
- 发布后再跑 `sync-site.sh --no-build` 才算上线
- **不要 git push / git commit**：提交和推送由外层 `run-daily.sh` 重试完成（这台机器到 GitHub 实测三成到一半的连接会超时，
  推不上去不影响当天上线，下一轮或人工补推）
- 只许改本版块的文件，不许 `--allow-bad-links` 硬发

### 5.1 手动试跑

整条链（会依次发四份）：

```bash
sudo systemctl start kaixinguor-daily-chain.service
journalctl -u kaixinguor-daily-chain.service -f
tail -f /var/log/kaixinguor/chain-latest.log
```

只跑一份（排障用）：

```bash
sudo systemctl start kaixinguor-daily@economy.service
journalctl -u kaixinguor-daily@economy.service -f
tail -f /var/log/kaixinguor/economy-latest.log
```

`run-daily.sh` 每份做五件事（链路里会带 `DEFER_PUSH=1`，把推送推迟到链路末尾）：`git pull --ff-only`（失败重试 3 次，仍失败就按当前树继续）→ `dsh headless`（3 小时上限）
→ `git add/commit`（链路里不 push，末尾统一推）→ 写
`/var/log/kaixinguor/<section>-<date>.log` → 校验文件存在且线上两个 URL 都 200 → 按结果发通知。
`run-chain.sh` 只负责排队：哪一份非零退出就停下，并告诉你从哪份续跑。

试跑完验收：

```bash
ls -l /home/project/kaixinguor.com/daily-ai/web/$(TZ=Asia/Shanghai date +%F)*.html
curl -sI https://kaixinguor.com/daily-ai/web/$(TZ=Asia/Shanghai date +%F) | head -1
```

> 同一天重跑是有意的覆盖：publish 会重新 build、commit、push，不会追加第二条。
> 重跑沿用当天已记录的窗口，不会把窗口拉长。

## 6. 补跑与续跑

- 关机错过 08:00 → 开机后 `Persistent=true` 立刻补跑整条链
- 关机三天 → 只补最近一次，不会补出三期
- 链路跑到一半机器重启 → systemd 不会自动续跑；重启后手动从断点接着跑：

```bash
# 修好问题后，从失败的那一份开始
sudo -u kaixinguor /opt/kaixinguor/bin/run-chain.sh education

# 或者只补某一份
sudo systemctl start kaixinguor-daily@education.service
```

`run-chain.sh <section>` 会从指定版块开始，按 AI → 经济 → 教育 → 心理 的剩余顺序继续。

演练（会真的发四期，挑能接受的时间）：

```bash
sudo systemctl stop kaixinguor-daily-chain.timer
sudo systemctl start kaixinguor-daily-chain.service
journalctl -u kaixinguor-daily-chain.service -f
sudo systemctl start kaixinguor-daily-chain.timer
```

## 7. Watchdog（可选，但建议装）

`kaixinguor-watchdog.timer` 每天 11:30 检查当天四份日报（AI 日报、经济日报、教育日报、心理学日报，各要中英文两个文件）：

- 都齐了：什么都不做；
- 有缺的：等 15 分钟（给开机后才开始生成的任务留时间），仍缺就发一条 failure 通知，写明缺哪一份；同一天只发一次；
- 服务器 11:30 后才开机：`Persistent=true` 会立即补跑 watchdog，再等 15 分钟。

手动测试：

```bash
sudo -u kaixinguor -H SITE_DIR=/opt/kaixinguor/site \
  STATE_DIR=/var/lib/kaixinguor \
  /opt/kaixinguor/bin/watchdog.sh
```

## 9. 安全

- **不要把 4096 端口暴露公网**；只绑 `127.0.0.1`，用 SSH 隧道。DSH Web 等于一个能执行 shell 的管理界面。
- 服务跑在专用用户 `kaixinguor`，不要用 root。
- `dsh.env` / `notify.env` 权限 600，属主 `kaixinguor`。
- GitHub 用 Deploy Key，只给这一个仓库写权限；不要用个人全权限 token。
- 服务器防火墙只开 SSH（必要时 80/443 给网站），4096 不开。
- 如果一定要远程访问 UI，用 Caddy/Nginx 加 TLS + Basic Auth + IP allowlist，并清楚风险。

## 10. 为什么当初写的是 Web + schedule，现在换成 headless

本文早先的版本主张"常驻 `dsh web` + 会话里的 schedule"，理由是 headless profile 不带 web 搜索/抓取。
2026-11-26 在服务器上实测 `dsh --profile headless --dump-default-config`，这个前提不成立：
`web-search-deepseek`、`web-fetch-http`、`tool-web`、`dsh-skill` 都在 headless profile 里。

换掉 Web + schedule 的实际原因：

1. **无人值守不该依赖 UI**：schedule 和 Session 绑定，建任务要开 Web 点界面；Session 一旦归档任务就没了。
2. **排障链路短**：timer + 一次进程，`journalctl` 直接看完整 stdout/stderr，退出码可判断成败。
3. **省内存**：这台机器总共 1.9G，还有 mysql；不需要为了定时任务常驻一个 Web 进程。
4. **补跑语义一样**：`Persistent=true` 和 DSH schedule 都是"错过只补最近一次"。

需要交互时仍然可以用 Web：`sudo systemctl start kaixinguor-dsh`，
然后 `ssh -L 4096:127.0.0.1:4096 root@39.107.233.27` 打开 `http://127.0.0.1:4096`（带启动日志里的 token）。

## 11. 故障排查

先看这一轮到底停在哪：

```bash
tail -80 /var/log/kaixinguor/ai-latest.log          # 换成 economy / education / psychology
systemctl status kaixinguor-daily@ai.service --no-pager
```

| 现象 | 先看 |
|---|---|
| 08:00 没触发 | `systemctl list-timers 'kaixinguor-*'`；timer 是否 `enabled`；机器当时是否开着 |
| 开机后没补跑 | `Persistent=true` 是否还在；`journalctl -u kaixinguor-daily@ai` 有没有 "Missed" 记录 |
| `git pull 失败` | 服务器仓库和 GitHub 分叉了（多半是上一轮 push 失败又改了文件）；`git -C /opt/kaixinguor/site status` 看清楚再处理 |
| 生成失败 | 日志里往上翻第一条报错；链接检查挂了就换源，别用 `--allow-bad-links` |
| 推送失败 | `sudo -u kaixinguor -H ssh -T git@github.com`；Deploy Key 是否有写权限 |
| 网站没更新 | `ls -l /home/project/kaixinguor.com/daily-ai/web/<date>.html`；`sync-site.sh` 有没有报权限错；再 `curl -sI https://kaixinguor.com/...` |
| 没有通知 | `/etc/kaixinguor/notify.env` 权限 600、内容对不对；`/opt/kaixinguor/bin/notify.sh success 测试`；`journalctl -t kaixinguor-notify` |
| 跑到一半被杀 | 机器内存不够被 OOM：`dmesg -T | grep -i oom`；swap 是否还在（`swapon --show`） |
| 某条来源一直超时 | 这台机器实测 `nytimes.com`、`reuters.com` 不通，换同事件的一级源；不要 `--allow-bad-links` |
| 模型/检索报 401 | `dsh.env` 里的 `DEEPSEEK_API_KEY` 失效或没读到 |
