# 每天自动发布四份日报（Ubuntu + DSH）

> **当前状态：已部署（2026-11-26）。** 服务器 `39.107.233.27` 上 `dsh headless` 由 systemd timer 驱动，
> 每天 08:00 / 08:30 / 09:00 / 09:30（Asia/Shanghai）各跑一份日报并同步到 nginx；本文就是现在的实现说明。
> 目标：每天 **08:00 发 AI 日报、08:30 发经济日报、09:00 发教育日报、09:30 发心理学日报**（Asia/Shanghai），都是中英双语；服务器没开机时，开机后补跑最近一次；成功/失败都有手机通知。
>
> **和 Cloudflare 时代的区别（重要）**：`publish-*.mjs --push` 只推 GitHub，线上不会变。线上是这台 ECS 的
> `/home/project/kaixinguor.com`，由 nginx 直接服务，**没有** GitHub → 服务器的自动同步。
> 所以服务器上的日报任务最后必须多跑一步 `deploy/daily/sync-site.sh`（build + stage + rsync 到 nginx 目录），
> 否则日报提交了、站点还是旧的。
> 架构：**systemd timer + `dsh headless`**（不是 cron，也不是 Web 里的 schedule，理由见下节）。
> 手动一次性触发四份时，按 [每日四报统一规则](每日四报统一规则.md) 执行；自动任务是 08:00 / 08:30 / 09:00 / 09:30 的错峰方案。

## 为什么是 systemd timer + `dsh headless`

实测（2026-11-26，服务器上的 `@deepseek-ai/dsh@0.2.0-rc.2`）：`dsh --profile headless --dump-default-config`
里带着 `web-search-deepseek`、`web-fetch-http`、`tool-web`、`dsh-skill`，以及 bash / 文件读写工具。
"headless 没有检索能力"的前提不成立，所以一份日报可以一个进程跑完就退出。

| 方案 | 错过补跑 | 日志 | 需要常驻 UI | 结论 |
|---|---|---|---|---|
| cron | 不会 | 自己重定向 | 否 | 不用 |
| Web 里的 DSH schedule | 补最近一次 | 打开 Web 看 | 是，会话不能归档 | 能用，但依赖 UI |
| **systemd timer + `dsh headless`** | `Persistent=true` 补最近一次 | journald + 文件 | 否 | **当前实现** |

```
systemd timers（Asia/Shanghai）
  ├─ 08:00 kaixinguor-daily@ai.service
  │    └─ run-daily.sh ai
  │         ├─ git pull --ff-only              # 先对齐 Mac 上的文档/模板
  │         ├─ dsh headless <prompts/ai.txt>   # 检索、核验、双语、publish --push
  │         └─ 提示词内调用 sync-site.sh --no-build  # dist 同步到 nginx
  ├─ 08:30 kaixinguor-daily@economy.service
  ├─ 09:00 kaixinguor-daily@education.service
  ├─ 09:30 kaixinguor-daily@psychology.service
  └─ 11:30 kaixinguor-watchdog.timer           # 四份缺任何一份就发 failure

kaixinguor-dsh.service（dsh web）默认不启用，只在排障时手动 start + SSH 隧道。
```

错开 30 分钟的原因：后一份要读前一份已发的内容，避免同一件事写两遍；也避免四个重任务同时抢模型和这台 2G 内存的机器。

## 0. 前提

- Ubuntu 22.04 / 24.04，能 sudo；
- 一个能写 `kaixinguor.com` 仓库的 GitHub 账号（建议用 Deploy Key，只给这一个仓库写权限）；
- DeepSeek API Key（DSH 的模型和 web search 都用它）；
- 一个通知通道：Bark / ntfy / 飞书机器人 / Telegram 任选；
- 服务器能访问 `api.deepseek.com`、GitHub、新闻源。

以下命令默认仓库在 `/opt/kaixinguor/site`，运行用户 `kaixinguor`。路径可以换，但服务文件、脚本和文档要一起改。

## 5. 任务书与试跑

四份日报的"任务书"在 `deploy/daily/prompts/{ai,economy,education,psychology}.txt`，
安装到 `/opt/kaixinguor/prompts/`。`run-daily.sh` 会把里面的 `__DATE__` 换成当天日期再交给 `dsh headless`。

任务书里写死了这些，改流程就改这里：

- 窗口终点=现在，起点接上一期 `windowEnd`；只收窗口内发布的报道
- 每条必须打开原文核对标题/时间/首段，打不开就换源或删条
- 中英成对、期号 +1、发布前 `parseIssue` / `coverage check` / `check-links` / `style` 全绿
- 发布后再跑 `sync-site.sh --no-build` 才算上线
- 只许改本版块的文件，不许 `--allow-bad-links` 硬发

安装/更新（幂等）：

```bash
cd /opt/kaixinguor/site
sudo git pull --ff-only                      # 以仓库里的版本为准
sudo bash deploy/daily/install-server.sh
```

它会装脚本到 `/opt/kaixinguor/bin`、提示词到 `/opt/kaixinguor/prompts`、单元到
`/etc/systemd/system`，并启用 4 个 timer + watchdog。

看下次触发时间：

```bash
systemctl list-timers 'kaixinguor-*' --no-pager
```

### 5.1 手动试跑一份

```bash
sudo systemctl start kaixinguor-daily@ai.service
```

> 注意重跑会用"现在"当窗口终点，和当天已发那期的窗口不完全一致，属正常。

## 6. 补跑行为

四个 timer 都是 `Persistent=true`，规则是"欠一次补一次"：

- 07:55 关机、08:10 开机 → AI 日报的 08:00 立刻补跑；经济/教育/心理按各自时间正常触发
- 08:00 时机器没开、08:40 才开 → 08:00 和 08:30 两份都补跑，几乎同时启动
- 关机三天 → 每个 timer 只补最近一次，不会补出三期
- 同一时间段重复触发不会叠加，systemd 会复用同一个 service

演练（会真的发一期，选能接受的时间）：

```bash
sudo systemctl stop kaixinguor-daily@ai.timer     # 先关掉 timer 免得打架
sudo systemctl start kaixinguor-daily@ai.service  # 手动补跑
journalctl -u kaixinguor-daily@ai.service -f
sudo systemctl start kaixinguor-daily@ai.timer    # 恢复
```

## 7. Watchdog（可选，但建议装）

`kaixinguor-watchdog.timer` 每天 11:30 检查当天四份日报（AI 日报、经济日报、教育日报、心理学日报，各要中英文两个文件）：

- 都齐了：什么都不做；
- 有缺的：等 15 分钟（给开机后才开始生成的任务留时间），仍缺就发一条 failure 通知，写明缺哪一份；同一天只发一次；
- 服务器 11:30 后才开机：`Persistent=true` 会立即补跑 watchdog，再等 15 分钟。

手动测试：

```bash
sudo -u kaixinguor -H SITE_DIR=/opt/kaixinguor/site \
  STATE_DIR=/var/lib/kaixinguor \
  /opt/kaixinguor/bin/watchdog.sh
```

## 9. 安全

- **不要把 4096 端口暴露公网**；只绑 `127.0.0.1`，用 SSH 隧道。DSH Web 等于一个能执行 shell 的管理界面。
- 服务跑在专用用户 `kaixinguor`，不要用 root。
- `dsh.env` / `notify.env` 权限 600，属主 `kaixinguor`。
- GitHub 用 Deploy Key，只给这一个仓库写权限；不要用个人全权限 token。
- 服务器防火墙只开 SSH（必要时 80/443 给网站），4096 不开。
- 如果一定要远程访问 UI，用 Caddy/Nginx 加 TLS + Basic Auth + IP allowlist，并清楚风险。

## 10. 为什么当初写的是 Web + schedule，现在换成 headless

本文早先的版本主张"常驻 `dsh web` + 会话里的 schedule"，理由是 headless profile 不带 web 搜索/抓取。
2026-11-26 在服务器上实测 `dsh --profile headless --dump-default-config`，这个前提不成立：
`web-search-deepseek`、`web-fetch-http`、`tool-web`、`dsh-skill` 都在 headless profile 里。

换掉 Web + schedule 的实际原因：

1. **无人值守不该依赖 UI**：schedule 和 Session 绑定，建任务要开 Web 点界面；Session 一旦归档任务就没了。
2. **排障链路短**：timer + 一次进程，`journalctl` 直接看完整 stdout/stderr，退出码可判断成败。
3. **省内存**：这台机器总共 1.9G，还有 mysql；不需要为了定时任务常驻一个 Web 进程。
4. **补跑语义一样**：`Persistent=true` 和 DSH schedule 都是"错过只补最近一次"。

需要交互时仍然可以用 Web：`sudo systemctl start kaixinguor-dsh`，
然后 `ssh -L 4096:127.0.0.1:4096 root@39.107.233.27` 打开 `http://127.0.0.1:4096`（带启动日志里的 token）。

## 11. 故障排查

先看这一轮到底停在哪：

```bash
tail -80 /var/log/kaixinguor/ai-latest.log          # 换成 economy / education / psychology
systemctl status kaixinguor-daily@ai.service --no-pager
```

| 现象 | 先看 |
|---|---|
| 08:00 没触发 | `systemctl list-timers 'kaixinguor-*'`；timer 是否 `enabled`；机器当时是否开着 |
| 开机后没补跑 | `Persistent=true` 是否还在；`journalctl -u kaixinguor-daily@ai` 有没有 "Missed" 记录 |
| `git pull 失败` | 服务器仓库和 GitHub 分叉了（多半是上一轮 push 失败又改了文件）；`git -C /opt/kaixinguor/site status` 看清楚再处理 |
| 生成失败 | 日志里往上翻第一条报错；链接检查挂了就换源，别用 `--allow-bad-links` |
| 推送失败 | `sudo -u kaixinguor -H ssh -T git@github.com`；Deploy Key 是否有写权限 |
| 网站没更新 | `ls -l /home/project/kaixinguor.com/daily-ai/web/<date>.html`；`sync-site.sh` 有没有报权限错；再 `curl -sI https://kaixinguor.com/...` |
| 没有通知 | `/etc/kaixinguor/notify.env` 权限 600、内容对不对；`/opt/kaixinguor/bin/notify.sh success 测试`；`journalctl -t kaixinguor-notify` |
| 跑到一半被杀 | 机器内存不够被 OOM：`dmesg -T | grep -i oom`；swap 是否还在（`swapon --show`） |
| 模型/检索报 401 | `dsh.env` 里的 `DEEPSEEK_API_KEY` 失效或没读到 |

## 12. 最短路径清单

1. 装 Node 24（`>=24.9`）+ `npm i -g @deepseek-ai/dsh`（带 `--allow-scripts`）
2. 建 `kaixinguor` 用户、Deploy Key、clone 仓库、`chown` 站点目录
3. 写 `/etc/kaixinguor/dsh.env`（key）和 `notify.env`（Bark）
4. `sudo bash deploy/daily/install-server.sh`
5. `systemctl list-timers 'kaixinguor-*'` 确认 08:00 / 08:30 / 09:00 / 09:30 / 11:30
6. `sudo systemctl start kaixinguor-daily@ai.service` 手动跑一次，看日志、看线上页面、看手机通知
7. 找一天演练"8 点后开机补跑"
