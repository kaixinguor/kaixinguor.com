# 每天自动发布两份日报（Ubuntu + DSH）

> **当前状态：还没部署服务器，两份日报都是手动触发。本文是部署方案，不是现状。**  
> 目标：每天 **09:00 发 AI 日报、09:30 发经济日报**（Asia/Shanghai），都是中英双语；服务器没开机时，开机后补跑最近一次；成功/失败都有手机通知。  
> 推荐架构：**DSH Web 常驻 + DSH 内置定时任务**。不要再用 cron 触发生成，避免和 DSH 的调度重复。

## 为什么是 DSH schedule，而不是 cron

DSH 的定时任务（`schedule_create`）把任务存在原 Session 里。官方行为是：

- Host 重启后任务仍然存在；
- 到期时 Host 会恢复冷 Session 并投递；
- 错过的周期任务只补**最近一次**；
- 服务器 09:10 才开机，09:00 的任务会在开机后补跑。

这正是你要的“9 点后第一次开机时跑”。  
cron 不会补跑；systemd timer 可以 `Persistent=true`，但生成日报需要 DSH 的 web 搜索和写文件能力，还是让 DSH 自己调度更简单。

整体链路：

```
systemd
  └─ kaixinguor-dsh.service          # 常驻 dsh web，127.0.0.1:4096
       ├─ Session「AI 日报」
       │    └─ 每天 09:00 的 DSH 定时任务
       │         ├─ 检索、写作、校验、publish-daily --push
       │         └─ notify.sh success/failure
       └─ Session「经济日报」
            └─ 每天 09:30 的 DSH 定时任务
                 ├─ 检索、写作、校验、publish-economy --push
                 └─ notify.sh success/failure

kaixinguor-watchdog.timer (10:30)
  └─ 两份日报只要有一份没生成，等 15 分钟再检查，仍缺就 notify failure
```

## 0. 前提

- Ubuntu 22.04 / 24.04，能 sudo；
- 一个能写 `kaixinguor.com` 仓库的 GitHub 账号（建议用 Deploy Key，只给这一个仓库写权限）；
- DeepSeek API Key（DSH 的模型和 web search 都用它）；
- 一个通知通道：Bark / ntfy / 飞书机器人 / Telegram 任选；
- 服务器能访问 `api.deepseek.com`、GitHub、新闻源。

以下命令默认仓库在 `/opt/kaixinguor/site`，运行用户 `kaixinguor`。路径可以换，但服务文件、脚本和文档要一起改。

## 1. 基础环境

```bash
sudo apt update
sudo apt install -y curl git jq ca-certificates
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node -v
npm -v

sudo npm install -g @deepseek-ai/dsh
dsh --version
command -v dsh          # 通常是 /usr/local/bin/dsh
```

时区必须是北京时间；DSH 的 schedule 也会显式写 `Asia/Shanghai`：

```bash
sudo timedatectl set-timezone Asia/Shanghai
timedatectl
```

## 2. 用户、目录、仓库

```bash
sudo groupadd --system kaixinguor 2>/dev/null || true
sudo useradd -m -d /home/kaixinguor -s /bin/bash -g kaixinguor kaixinguor
sudo mkdir -p /opt/kaixinguor /etc/kaixinguor /var/lib/kaixinguor
sudo chown -R kaixinguor:kaixinguor /opt/kaixinguor /var/lib/kaixinguor
```

给 `kaixinguor` 生成部署密钥：

```bash
sudo -u kaixinguor -H mkdir -p /home/kaixinguor/.ssh
sudo -u kaixinguor -H chmod 700 /home/kaixinguor/.ssh
sudo -u kaixinguor -H ssh-keygen -t ed25519 -C "kaixinguor-daily@$(hostname)" -f /home/kaixinguor/.ssh/id_ed25519 -N ''
sudo -u kaixinguor -H cat /home/kaixinguor/.ssh/id_ed25519.pub
```

把公钥加到 GitHub 仓库：**Settings → Deploy keys → Add deploy key**，勾选 **Allow write access**。  
然后测试并 clone：

```bash
sudo -u kaixinguor -H ssh -T git@github.com
sudo -u kaixinguor -H git clone git@github.com:kaixinguor/kaixinguor.com.git /opt/kaixinguor/site
sudo -u kaixinguor -H git -C /opt/kaixinguor/site config user.name "kaixinguor daily"
sudo -u kaixinguor -H git -C /opt/kaixinguor/site config user.email "daily@kaixinguor.com"
```

日报的源文件放在仓库外（和 Mac 上一样）：

```bash
sudo -u kaixinguor -H mkdir -p /opt/kaixinguor/ai-daily
```

测试一次发布脚本能不能跑：

```bash
sudo -u kaixinguor -H bash -lc 'cd /opt/kaixinguor/site && node scripts/build.mjs --check'
```

## 3. 环境文件

### 3.1 DSH 的 Key

```bash
sudo install -m 600 -o kaixinguor -g kaixinguor /dev/null /etc/kaixinguor/dsh.env
sudo -u kaixinguor -H tee /etc/kaixinguor/dsh.env >/dev/null <<'EOF'
DEEPSEEK_API_KEY=sk-REPLACE_ME
TZ=Asia/Shanghai
EOF
```

> 如果 DSH 用的是账号登录而不是 API Key，至少也要保证服务用户能读到它自己的凭据；最稳的是给服务器单独配一个 API Key。

### 3.2 通知通道

```bash
sudo install -m 600 -o kaixinguor -g kaixinguor /dev/null /etc/kaixinguor/notify.env
sudo -u kaixinguor -H tee /etc/kaixinguor/notify.env >/dev/null <<'EOF'
# 三选一，或都填
BARK_URL=https://api.day.app/REPLACE_ME/
# NTFY_URL=https://ntfy.sh/kaixinguor-REPLACE_RANDOM
# FEISHU_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/REPLACE_ME
EOF
```

国内网络下，**Bark（iPhone）或飞书机器人**最稳；ntfy 公共实例和 Telegram 是否可达要看服务器网络。  
`notify.env` 里不要用可猜的 ntfy topic；topic 本身当密码用。

## 4. 安装服务

```bash
cd /opt/kaixinguor/site

sudo install -d -o kaixinguor -g kaixinguor /opt/kaixinguor/bin
sudo install -m 755 -o kaixinguor -g kaixinguor deploy/daily-ai/notify.sh   /opt/kaixinguor/bin/notify.sh
sudo install -m 755 -o kaixinguor -g kaixinguor deploy/daily-ai/watchdog.sh /opt/kaixinguor/bin/watchdog.sh

sudo install -m 644 deploy/daily-ai/kaixinguor-dsh.service          /etc/systemd/system/
sudo install -m 644 deploy/daily-ai/kaixinguor-watchdog.service     /etc/systemd/system/
sudo install -m 644 deploy/daily-ai/kaixinguor-watchdog.timer       /etc/systemd/system/

sudo systemctl daemon-reload
sudo systemctl enable --now kaixinguor-dsh.service
sudo systemctl enable --now kaixinguor-watchdog.timer

systemctl status kaixinguor-dsh.service --no-pager
journalctl -u kaixinguor-dsh.service -n 80 --no-pager
```

如果 `dsh` 不在 `/usr/local/bin/dsh`，改 `kaixinguor-dsh.service` 的 `ExecStart`，然后 `daemon-reload && restart`。

先测试通知脚本：

```bash
sudo -u kaixinguor -H /opt/kaixinguor/bin/notify.sh success "kaixinguor 通知测试"
```

手机应该收到；没收到就看：

```bash
journalctl -t kaixinguor-notify -n 20 --no-pager
```

## 5. 打开 Web UI，创建定时任务

DSH Web 只监听 `127.0.0.1:4096`，不要直接暴露公网。用 SSH 隧道：

```bash
ssh -L 4096:127.0.0.1:4096 kaixinguor@<server-ip>
```

本机浏览器打开 `http://127.0.0.1:4096`。  
如果 DSH 输出带 token 的 URL，用那个 URL。

1. 新建一个会话，确认工作目录是 `/opt/kaixinguor/site`。  
2. 在会话里发这句话，让 Agent 创建定时任务：

```text
请创建一个每天 09:00（Asia/Shanghai）的定时任务，标题「AI 日报 · 每日发布」。

任务指令：
执行今天的 AI 日报任务。请完整阅读并严格遵循
/opt/kaixinguor/site/docs/每日生成任务.md
里的时间窗口、检索、核验、写作、链接检查、发布和通知流程。
如果当前时间早于 09:00，跳过补跑，等待当天 09:00。
```

3. 确认 Agent 调用了 `schedule_create`，参数是：
   - 频率：daily
   - 时间：`09:00:00`
   - 时区：`Asia/Shanghai`
   - 标题：`AI 日报 · 每日发布`
4. 到 Web UI 的 **Automation tasks / 自动化任务** 里确认任务存在，且下次运行时间是下一个 09:00。  
5. 这个 Session 不要归档、不要删除；任务和 Session 绑定。

> 第一次创建时，如果已经过了 09:00，第一次触发会是明天 09:00，这是正常的。  
> 想验证，可以再让 Agent 创建一个“2 分钟后执行”的一次性测试提醒，确认能收到通知后再删掉。

### 5.2 第二个会话「经济日报」（每天 09:30）

经济日报单独一个 Session、单独一个定时任务，和 AI 日报并行。错开 30 分钟，避免两个重任务同时抢模型和网络。

1. 在 Web UI **新建一个会话**「经济日报」，工作目录仍然是 `/opt/kaixinguor/site`。  
2. 在这个会话里发：

```text
请创建一个每天 09:30（Asia/Shanghai）的定时任务，标题「经济日报 · 发布」。

任务指令：
执行今天的经济日报任务。请完整阅读并严格遵循
/opt/kaixinguor/site/docs/每日生成任务-经济日报.md
里的时间窗口、检索、与 AI 日报的分工、写作、链接检查、发布和通知流程。
如果当前时间早于 09:30，跳过补跑，等待当天 09:30。
```

3. 确认 `schedule_create` 的参数是：频率 `daily`、时间 `09:30:00`、时区 `Asia/Shanghai`、标题 `经济日报 · 发布`。
4. 到 Automation tasks 里确认两个任务都在，下次运行时间分别是 09:00 和 09:30。
5. 两个 Session 都不要归档、不要删除；任务和 Session 绑定。

> 两个任务必须**分开两个 Session**。放在同一个会话里，两个 schedule 混在一起，出错时很难分清是哪份日报的问题。  
> 经济日报的母版目录是 `/opt/kaixinguor/economy-daily/`，和 `/opt/kaixinguor/ai-daily/` 平级，要一起备份。

## 6. 补跑行为

DSH 的定时任务在 Host 重启后仍然存在；到期时恢复冷 Session 并投递，周期任务只补最近一次。

所以：

- 08:55 关机，09:10 开机 → 09:00 的任务会在开机后补跑；
- 09:00 时 DSH 服务没启动，09:05 启动 → 同上；
- 关机 3 天 → 只补最近一次，不会把 3 天都生成；
- 08:00 开机 → 可能补昨天 9 点的提醒；`每日生成任务.md` 里已经加了“早于 09:00 就跳过”的保护，不会提前生成今天的两份。

建议实际演练一次：

```bash
# 在 08:55 左右
sudo systemctl stop kaixinguor-dsh.service

# 09:10 左右
sudo systemctl start kaixinguor-dsh.service
journalctl -u kaixinguor-dsh.service -f
```

看当天 `daily-ai/YYYY-MM-DD.html` 是否出现、手机是否收到成功通知。演练会真的发一期日报，选一个可以接受的时间做。

## 7. Watchdog（可选，但建议装）

`kaixinguor-watchdog.timer` 每天 10:30 检查当天两份日报（AI 日报、经济日报，各要中英文两个文件）：

- 都齐了：什么都不做；
- 有缺的：等 15 分钟（给开机后才开始生成的任务留时间），仍缺就发一条 failure 通知，写明缺哪一份；同一天只发一次；
- 服务器 10:30 后才开机：`Persistent=true` 会立即补跑 watchdog，再等 15 分钟。

手动测试：

```bash
sudo -u kaixinguor -H SITE_DIR=/opt/kaixinguor/site \
  STATE_DIR=/var/lib/kaixinguor \
  /opt/kaixinguor/bin/watchdog.sh
```

## 8. 日常运维

```bash
# 服务日志
journalctl -u kaixinguor-dsh.service -n 200 --no-pager
journalctl -u kaixinguor-dsh.service -f

# 定时器
systemctl list-timers kaixinguor-watchdog.timer --no-pager

# 仓库状态
sudo -u kaixinguor -H git -C /opt/kaixinguor/site status --short
sudo -u kaixinguor -H git -C /opt/kaixinguor/site log -1 --oneline

# 当天文件
ls -lh /opt/kaixinguor/site/daily-ai/$(TZ=Asia/Shanghai date +%F)*.html
```

升级 DSH 前先看版本，别在 09:00 前后升级：

```bash
dsh --version
sudo npm install -g @deepseek-ai/dsh@<version>
sudo systemctl restart kaixinguor-dsh.service
```

**备份**：

- `/opt/kaixinguor/site`（仓库 + 生成物）
- `/opt/kaixinguor/ai-daily`、`/opt/kaixinguor/economy-daily`（源稿）
- `/var/lib/kaixinguor/.dsh`（Session、定时任务、凭据）
- `/etc/kaixinguor/*.env`（单独安全备份，不要进 git）

## 9. 安全

- **不要把 4096 端口暴露公网**；只绑 `127.0.0.1`，用 SSH 隧道。DSH Web 等于一个能执行 shell 的管理界面。
- 服务跑在专用用户 `kaixinguor`，不要用 root。
- `dsh.env` / `notify.env` 权限 600，属主 `kaixinguor`。
- GitHub 用 Deploy Key，只给这一个仓库写权限；不要用个人全权限 token。
- 服务器防火墙只开 SSH（必要时 80/443 给网站），4096 不开。
- 如果一定要远程访问 UI，用 Caddy/Nginx 加 TLS + Basic Auth + IP allowlist，并清楚风险。

## 10. 为什么不用 `dsh headless` + systemd timer

`dsh headless` 也能一次性跑任务，但默认 headless profile 不带 web 搜索/抓取工具；要做得先给 profile 加 web bundle，维护成本更高。  
DSH Web + schedule 已经提供：

- 常驻、开机自启；
- 任务持久化；
- Host 重启后恢复冷 Session；
- 错过只补最近一次。

这比再写一套 headless 调度更稳。如果以后确实想去掉 Web UI，再单独做 headless profile + systemd timer，`Persistent=true` 同样能补跑，那是第二步。

## 11. 故障排查

| 现象 | 先看 |
|---|---|
| 09:00 没触发 | `systemctl status kaixinguor-dsh`；Automation tasks 里任务是否还在；Session 是否被归档 |
| 开机后没补跑 | 服务是否 `enabled`；`journalctl -u kaixinguor-dsh`；任务下次运行时间 |
| 生成失败 | `journalctl`；DSH Session 里的错误；`publish-daily` 的链接检查输出 |
| 没有通知 | `notify.env` 权限/内容；`notify.sh` 手动测试；`journalctl -t kaixinguor-notify` |
| 推送失败 | `sudo -u kaixinguor -H ssh -T git@github.com`；Deploy Key 是否有写权限；`git status` |
| 网站没更新 | Cloudflare 部署延迟；`curl -I https://kaixinguor.com/`；GitHub 提交是否成功 |

## 12. 最短路径清单

1. 装 Node 22 + `@deepseek-ai/dsh`；
2. 建 `kaixinguor` 用户、Deploy Key、clone 仓库；
3. 写 `dsh.env`、`notify.env`；
4. 装 3 个 systemd 文件，启动 DSH 和 watchdog；
5. SSH 隧道打开 Web UI，建两个 Session，分别创建 09:00 和 09:30 的定时任务；
6. 手动测试通知；
7. 找一天演练“9 点后开机补跑”。

做完这 7 步，两份日报就会在服务器上每天 09:00 / 09:30 自动跑；服务器没开则开机后补最近一次，成功/失败都会推送到手机。
