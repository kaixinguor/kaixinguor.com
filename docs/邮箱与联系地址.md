# 邮箱与联系地址

> 域名邮箱走 **Cloudflare Email Routing**，只做收信转发，**不能主动发信**。
> 一个域名只能有一套 MX——以后要换成真邮箱（iCloud+ / Zoho / Workspace）时，
> 必须先到 Cloudflare 把 Email Routing **Disable**，否则新旧 MX 会打架。

---

## 现状

| 项目 | 值 |
|---|---|
| DNS 托管 | Cloudflare（`cruz.ns.cloudflare.com` / `howard.ns.cloudflare.com`） |
| 邮件服务 | Cloudflare Email Routing（账号级，免费） |
| MX | `route1.mx.cloudflare.net`（98）、`route2`（100）、`route3`（85） |
| SPF | `v=spf1 include:_spf.mx.cloudflare.net ~all` |
| DKIM | `cf2024-1._domainkey.kaixinguor.com`（由 Email Routing 托管） |
| DMARC | 未配置（可选：`_dmarc` = `v=DMARC1; p=none; rua=mailto:…`） |
| 信最终去向 | `ling.wang.nj@gmail.com`（已 Verify） |

这些记录在 Cloudflare DNS 里带 🔒 锁，由 Email Routing 托管，**不要手改**；Disable 时会自动删除。

## 前缀约定：一个产品一个地址

产品相关的用产品名，愿望相关的用 `wish`。三条规则都是 `Send to an email` →
`ling.wang.nj@gmail.com`，在 **Email Routing → Routing rules** 里管理。

| 地址 | 归属 | 用在哪 |
|---|---|---|
| `wish@kaixinguor.com` | 许愿池 | [wish.html](../wish.html) 表单提交 |
| `hark@kaixinguor.com` | 课堂字幕（Hark） | [hark/index.html](../hark/index.html)、[hark/privacy.html](../hark/privacy.html)、[download.html](../download.html) |
| `snipread@kaixinguor.com` | 摘读（SnipRead） | [snipread/index.html](../snipread/index.html)、[support.html](../snipread/support.html)、[privacy.html](../snipread/privacy.html) |
| Catch-all | 兜底 | 任何打错的前缀，都落到同一个 Gmail |

新前缀要么在 Routing rules 里加一条，要么靠 Catch-all 兜住（免费，不限量）。
建议开 **Subaddressing**（Settings 里），这样 `hark+bug@kaixinguor.com` 也能命中 `hark@`。

---

## 发信的边界

Email Routing 不提供 SMTP，站上的 `mailto:` 只是「让访客写给你」，不会从
`@kaixinguor.com` 发出任何邮件。真要主动发信（内测通知、日报订阅确认）时：

1. 先在 Cloudflare **Disable Email Routing**（MX 记录会清掉）
2. 再接 iCloud+ 自定义域名 / Zoho / Google Workspace，按其后台写新的 MX + SPF + DKIM
3. 或者用 Resend / Postmark 这类 ESP 只做「发」，收信仍留在原处

---

## 排查

- 信没到：Cloudflare → **Email Routing → Activity log**，看是 `delivered`、`dropped` 还是被 `spam` 挡了，比翻 Gmail 垃圾箱准。
- 规则不生效：目标地址没 Verified 时，规则会被自动禁用。
- 换了 Gmail 收信：在 Destination addresses 里加新的并验证，再回来改每条规则的目标，最后删掉旧地址（删地址会自动禁用用它的规则）。

## 许愿表单：`POST /api/wish`

[wish.html](../wish.html) 的「发送」现在会先弹确认窗（可改标题和正文），点「直接发送」才 POST 到
`/api/wish`。

站点是 **Workers + 静态资源**（不是 Pages Functions），四个零件：

| 文件 | 作用 |
|---|---|
| [`worker/index.js`](../worker/index.js) | Worker 入口，只拦 `/api/wish`，其余交给 `env.ASSETS.fetch()` |
| [`worker/wish.js`](../worker/wish.js) | 校验 → 发信 → 回 JSON 的实际逻辑 |
| [`wrangler.jsonc`](../wrangler.jsonc) | `main` 指向入口，`assets.binding = ASSETS`，`run_worker_first: ["/api/*"]` |
| [`.assetsignore`](../.assetsignore) | 把 `worker/` 排除，别让源码变成可下载的静态文件 |

它只做三件事：校验 → 发一封邮件到 `WISH_TO` → 回 JSON。

表单只收集五个问题，不再问访客的联系方式；想直接聊的人用页面底部的 `contact@` 或微信号主动找过来。
（`contact` 字段服务端仍兼容，留空就不设 Reply-To。）

| 情况 | 返回 | 前端表现 |
|---|---|---|
| 正常 | `200 {ok:true}` | 「已发出，谢谢」，1 秒后关窗 |
| 没配发信 | `501 {error:"not_configured"}` | 提示先去「复制 / 用邮件 App 打开」 |
| 路由不存在（纯静态宿主） | `404` / `405` | 同上，自动降级 |
| 内容空 / 太长 / 别的站调用 / 刷太快 | `400 / 403 / 429` | 显示具体原因 |

> 405 是 Workers 静态资源对 POST 的默认答复——看到它就说明 `/api` 没进 Worker 路由。
>
> `run_worker_first: ["/api/*"]` 是硬要求：不写它，Worker 会接管整站请求，
> 2026-11-02 就是这么把 `/`、`/wish` 全拖超时的（本地 `wrangler dev` 复现不出来）。

### 构建与部署（Workers Builds）

| 项 | 值 |
|---|---|
| Build command | `node scripts/build.mjs && node scripts/stage.mjs` |
| Deploy command | `npx wrangler deploy` |
| Root directory | `/`（仓库根，也就是 `site/`） |
| 环境变量 | `NODE_VERSION=20` |

`npx wrangler deploy` 读 `wrangler.jsonc`，把 Worker 和静态资源**一次性**发上去。
`stage.mjs` 产出的 `dist/site/` 是给 ECS / 打包用的，Workers 这条链路里被 `.assetsignore` 排除，跑它无害。

### 发信的三条通道（代码按优先级自动选）

**A. `send_email` 绑定 —— 最干净，纯 Cloudflare，不需要 token**

1. Compute → **Email Service → Email Sending → Onboard Domain**
2. 把 [`wrangler.jsonc`](../wrangler.jsonc) 里注释掉的 `send_email` 段解开
3. 重新部署

`destination_address` 限定只能发到那一个已验证地址，比拿 token 安全。

**B. REST + API Token —— 不想改配置时**

1. onboard 同 A
2. My Profile → API Tokens → Create Token，权限 **`Email Sending: Edit`**
3. Workers 项目 → Settings → **Variables and Secrets** 加 `CF_API_TOKEN`（Secret）、`CF_ACCOUNT_ID`

**C. Resend —— 第三方，但不用碰 Cloudflare 的邮件后台**

1. [resend.com](https://resend.com) → Domains → Add Domain → `kaixinguor.com`，按记录加 DNS
2. Verified 后建 sending key
3. 加 `RESEND_API_KEY`（Secret）

> 三种方式都要求「发信域名已 onboard」——`WISH_FROM` 默认 `wish-form@kaixinguor.com`，
> 如果域名没在 Email Sending 里验证过，发出去会被拒（`E_SENDER_NOT_VERIFIED` / `10203`）。

**改完必须重新部署**：变量和绑定都不会热加载到已有部署。

> `WISH_TO` 默认是 `ling.wang.nj@gmail.com`，它必须是 Email Routing 里**已验证的 destination**——发给已验证地址是免费的。
> 换成别的地址前，先去 Destination addresses 里验证。

### 环境变量

| 名字 | 默认值 | 说明 |
|---|---|---|
| `WISH_TO` | `ling.wang.nj@gmail.com` | 收信地址，必须是已验证 destination |
| `WISH_FROM` | `wish-form@kaixinguor.com` | 发信人，它的域必须已在 Email Sending 里 onboard |
| `CF_API_TOKEN` | — | 权限 `Email Sending: Edit` |
| `CF_ACCOUNT_ID` | — | Cloudflare 账号 ID |
| `RESEND_API_KEY` | — | Resend 分支用 |
| `EMAIL`（绑定） | — | 在 `wrangler.jsonc` 里配 |

优先级：`EMAIL` → `CF_API_TOKEN` → `RESEND_API_KEY`。三套都没配就返回 501，页面提示改用「复制 / 邮件 App」。

### 验证

```bash
curl -sS -X POST https://kaixinguor.com/api/wish \
  -H 'content-type: application/json' \
  -d '{"subject":"测试","body":"hello"}'
# 期望：{"ok":true,...}
```

返回 `501` 说明密钥还没配（或没重新部署）；`502` 会带上服务商的具体错误码；`403` 说明不是从 `kaixinguor.com` 发的（本地调试放行 `localhost`）。
