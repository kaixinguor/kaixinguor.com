## 判断规则

**三次法则：同一个需求出现 3 次以上，才值得做成产品。**

第一次是巧合，第二次是信号，第三次才是需求。

四条硬性筛选（缺一条就打问号）：

| 问题 | 为什么问 |
|---|---|
| 现在怎么解决的 | 没有替代方案的需求，往往是伪需求 |
| 多久遇到一次 | 一年一次的事，不值得做产品 |
| 愿付多少 | 决定它是产品还是定制 |
| 什么设备 | Windows 用户的需求直接排除，我们只做苹果 |

## 分流

| 判断 | 去哪 |
|---|---|
| 落在"学习/教书"里 + 有人愿意付钱 | 做成产品 |
| 落在里面但只有一个人要 | 报价做定制 |
| 系统自带已经能做 | 直接告诉用户别做（见 [苹果能力清单](苹果能力清单.md)） |
| 落在外面（跟学习教书无关） | 不做，除非对方出定制价 |

## 复盘

每收到 10 条，回头看一次：

- 有没有同一件事反复出现？（那就是下一个产品）
- 有没有人愿意为"更省事"付超过 ¥200？（那可能是定制客户）
- 有没有一批需求指向同一个系统缺口？（那可能是最好的机会）
