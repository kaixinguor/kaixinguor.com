月之暗面开放 Kimi K3.1 Pro 权重：2.8 万亿参数，BF16 权重约 5.6TB

11 月 5 日，月之暗面按 10 月 24 日发布时给出的承诺，在 Hugging Face 开放了 Kimi K3.1 Pro 的完整模型权重。模型采用混合专家架构，总参数 2.8 万亿，单次推理激活约 1040 亿参数，支持约 100 万 Token 上下文窗口，原生支持视觉理解。

与 K3 相比，K3.1 Pro 以 K3 为基座做了大规模联合强化学习后训练，覆盖数百个下游领域，并把部分全注意力层替换为门控稀疏注意力层，以降低长上下文建模的开销。可下载不等于可本地运行：2.8 万亿参数以 BF16 存储约 5.6TB，即使 INT4 量化也要约 1.4TB。

评测口径来自 Agent Arena：K3.1 Pro（Max）在开放权重模型中排第一、全部参评模型第 13；净改进率 +5.1%，上一代 K3（Max）为 +0.9%。分项上，衡量 Shell 命令执行可靠性的 Bash Reliability 从 -4.5% 升到 +7.9%，开放模型第一；用户满意度指标 Praise vs Complaint 从 +1.3% 升到 +7.7%；可操控性 Steerability 为 +6.5%，同样居开放模型首位。这套榜单不用成对盲投，而是从超过 1.75 万次真实长程智能体会话里取信号（用户确认、表扬与投诉、纠正指令、Shell 执行错误），再用随机化推断估算净改进率。

传统基准上：Terminal-Bench 4.0 得分 65.7%，高于 GPT-6 Astra 的 58.2%，与 Claude Opus 5.5 的 66.4% 相差不到 1 个百分点。同一天，华为宣布昇腾对 K3.1 Pro 实现 0 Day 推理适配，基于 vLLM Ascend 与 SGLang 支持 Atlas 800 A3、Atlas 900 A3 SuperPod 与昇腾 950 超节点部署；适配重点是模型新增的稀疏注意力路径与多模态推理，以及 KDA 线性注意力层、缓存管理与跨卡通信的协同优化。

看点开源界的参数纪录又往上跳了一格，但真正变的是「可及」的定义：2.8 万亿参数在 BF16 下 5.6TB，INT4 也要 1.4TB，个人开发者拿到的是权重文件而不是能跑的服务，能部署的是云厂商与超节点。工程上值得盯三件事：稀疏注意力在 100 万上下文下的实际显存曲线、昇腾 0-day 适配的算子覆盖度（是否只跑通了 batch=1 的演示）、以及 Agent Arena 这种「从真实会话取信号」的评测能不能替代成对盲测。对下游，最直接的影响是推理定价——能跑 2.8 万亿的供应商就那么几家，开源并不自动等于便宜。
另一个视角权重放出的同一天，国产超节点就有了可用的推理路径，模型与芯片的绑定在加速；这让「开源」在国内更像一次算力生态的排位赛，而不是纯粹的社区礼物。

OpenAI 收购 Pierre Computer：把 agent 的代码存储与版本控制收进 Codex

11 月 4 日，OpenAI 宣布计划收购开发者工具公司 Pierre Computer Company，条款未披露，交易仍需监管批准。观察者把这笔交易看作对微软 GitHub 的正面进攻——目标不是人类开发者的仓库，而是 agent 的仓库。

Pierre 运营一项云服务，供 AI agent 存放它们生成的代码，也能存许可证、界面设计文件等关联内容。按 Pierre 的说法，它的性能显著优于同类技术：帮客户 Lovable 把代码检索延迟降了约 70%。

它同时维护一批流行的开源库。其中两个——Trees 与 Diffs——正是 OpenAI Codex 编程工具界面的底座：Trees 负责文件夹导航（搜索、拖拽移动子目录、标记新增与更新文件），Diffs 负责差异展示。大型项目动辄数百个代码文件、几十层目录，这两个库决定了 agent 读写仓库时的交互效率。

把时间线拼起来看更清楚：Codex 这类 agent 成为高频提交者后，仓库的瓶颈从存储容量变成并发与延迟——多个 agent 要各开一条工作线、平行提交、随时回滚。OpenAI 收下「存 agent 产出」这一层，等于把 Codex 的前端（Trees/Diffs）与后端（Pierre 云服务）一起握住。

看点这不是买团队，是买 agent 的写入路径。人类开发者的 Git 工作流假设提交稀疏、分支少、冲突靠人解；agent 的工作流是提交密集、分支多、需要并排跑。谁掌握这一层，谁就掌握了 agent 的「记忆」与审计线索。接下来看两件事：Pierre 的云服务是否继续对第三方开放，以及 OpenAI 会不会把 Codex 的会话与提交历史做成可查询的仓库。对做 agent 工具的团队，这是一个明确的信号——基础设施的竞争正在从「模型加编排」下沉到「版本控制加存储」。

腾讯混元 Hy4 正式版发布：770B MoE，首次能看图、能操作电脑

11 月 4 日，腾讯发布混元 Hy4 正式版，官方称这是混元首次跻身最强开源模型之列。相比 8 月底的 Hy4 preview，正式版扩大了预训练与后训练规模，参数量来到 770B（MoE 架构，激活约 49B）。腾讯云开发者社区给出的规格显示，上下文突破 100 万 Token——TokenHub 侧最大输入约 960K、最大输出约 64K。

两项「第一次」是重点。视觉上，Hy4 把感知、推理与工具调用连起来，可做细粒度图像处理、复杂图表分析与带图的数学视觉推理；官方举的例子是在 28 亿像素航拍图里定位约 2 米大小的屋顶构件、以及重组 900 片拼图还原一幅画。操作上，Hy4 首次支持电脑操作（Computer Use），能结合图形界面与命令行使用软件，并针对 Blender、CAD 等专业软件和跨应用长程任务做了专项训练；腾讯云 Agent Runtime 团队为它搭了沙箱，部署数百款应用反复执行验证。

官方内部口径：WorkBuddy 办公协作评测平均 83.18 分、任务通过率 96.15%，12 个场景里 9 个国内第一；游戏开发场景提升 19.1%、GameLogic 提升 9.8%；「因猜测导致的错误率」从 23.1% 降到 5.6%。价格延续 preview：输入 6 元、输出 18 元每百万 Token，发布期有五折优惠。

权重尚未放出。腾讯说会「近期开源模型权重、发布系统卡片」，并称开源会重点关注网络与生物安全风险；更省成本的 Hy4 Flash 也在计划中。

看点770B 总参数、49B 激活，意味着单机八卡跑不动，服务成本由路由稀疏度决定（激活占比约 6.4%）。真正值得看的是 Computer Use 的训练方式：在沙箱里部署数百款软件、让模型反复执行，是拿环境换数据；这条路 Anthropic 与 OpenAI 都在走，差别在腾讯把 Blender、CAD 这类专业软件列进了主场景。对下游，如果 GUI 操作在真实软件上稳定，国内一批「RPA 加大模型」的产品会被直接替代；如果不稳定，它就只是一个会看图的聊天模型。开源权重的时间表是关键——没有权重，微调与私有化部署都无从谈起。

11/05 07:41 IT之家 ↗

OpenAI 推出 Images 2.6：ChatGPT 能直接做 GIF，每周出图 40 亿张

11 月 5 日，OpenAI 推出 Images 2.6 模型。ChatGPT 现在可以用一段提示词、或一张上传的照片直接生成 GIF 动图，并能调整动画速度、逐帧编辑、分享给他人；在此之前，ChatGPT 无法一步原生生成 GIF。官方给的例子是「你能做一只跳舞的猫的 GIF 吗」，生成后可以在几帧之间逐帧查看。

规模数字更能说明变化：OpenAI 称用户现在每周通过 ChatGPT 及其 API 生成超过 40 亿张图片，比 9 月报告的每周 30 亿张明显增长。更新正向所有 ChatGPT 与 Codex 用户推送，覆盖网页、桌面与移动端。

API 侧同时推出两个变体：GPT-Image-2.6 Flare 与 GPT-Image-2.6 Sunburst，分别对应更快的生成与更高的质量。

看点图像模型的竞争点正在从「画得好不好」转向「改得动不动」。GIF 看着是小事，实际把「一次生成」变成「一条时间轴」：模型要维持跨帧一致性，成本按帧数上涨，评测口径也从单图质量变成「动作是否连贯」。40 亿张/周是个该记住的容量数字——推理压力正从文本转到图像，而图像的单次成本远高于文本 token。对产品团队，这是「生成功能变成编辑功能」的又一例：能不能逐帧改、能不能保持一致，比能不能出图更决定留存。Flare 与 Sunburst 的分工值得等官方给出延迟与价格再判断。

Nothing 预告 12 月发布首款 AI 原生设备：没有屏幕，也不是 App

11 月 4 日，Nothing 创始人裴宇发文，预告公司首款 AI 原生产品将在 2026 年 12 月发布。他给的两条限定很清楚：没有屏幕，也不是一款软件应用；「它是一种工具，但带有定义 Nothing 产品的个性与用心」。

他的论证是产品史：新技术总是在工作中先被认可，再进入家庭——PC 先是电子表格与文字处理设备，很久以后才用来听音乐；手机先是车载电话，几十年后才进到青少年手里。AI 也一样，编程、IT、客服、法务，连口袋里那个聊天机器人本质上都是生产力工具。

问题在于「上下文缺口」：现在用 AI，一半的工作是把上下文敲进文本框，而最重要的上下文根本进不了模型——喝咖啡时想到的点子、随口说的一句话。所以他认为，人们每天随身携带的工具才是获取上下文最方便的入口，而不是文本框。

形态目前还是传闻。消息人士 Roland Quandt 称 Nothing 将推出两款智能眼镜：一款主打音频（音乐、通话、语音助手，配光致变色镜片），一款带摄像头（支持 ChatGPT 与翻译）。彭博社此前的报道称，Nothing 的智能眼镜把 AI 任务放在手机与云端处理，不配 AR 显示屏。

看点这条的价值不在产品，在论证。如果「上下文缺口」成立，AI 硬件的胜负手就不是模型能力，而是「能不能一直在场且不惹人烦」——常开麦克风、常开摄像头，换来的是隐私与续航两笔账。Nothing 选「没有屏幕」，等于放弃视觉输出，把交互压到语音与音频；这与 Humane、Rabbit 想替代手机的路线不同，它讲的是「补充上下文的入口」。12 月要看三件事：形态、续航，以及它是否要求用户一直戴着。

openJiuwen 上线「视听双流记忆」：按事件切分长视频，召回精度最高提升 45.7%

11 月 4 日，openJiuwen 的 AgentMemory 上线多模态记忆能力 OmniMem-Lens，版本号 0.2.0。它要解决的问题很具体：三个小时的视频，agent 怎么「记」。

通行做法是按固定时间窗口（比如一分钟）把长视频切开，让智能体分段记忆。openJiuwen 团队认为这带来两个硬伤：一是记忆被切碎，一段连贯的讲解在中间被切断，提问时只能拿到半段证据，容易产生幻觉；二是记忆被稀释，几秒钟的关键动作和前后几分钟无关画面打包在一起，检索时关键信息被噪音淹没。他们的说法是「agent 在按秒记视频，人在按事件理解视频」。

OmniMem-Lens 的做法是视听双流：视觉失灵时听觉顶上，听觉失灵时（比如无台词的镜头切换）视觉顶上，两路交叉判定事件边界，再按事件组织记忆与分层检索。官方口径的数字是：召回精度最高提升 45.7%，在线问答时延最高降低 97%。项目已在 GitCode 开源（openJiuwen/agent-memory），WorkSwarm 称即将支持对接。

看点这是把「记忆」从模型能力拆成系统能力的一次尝试：不换模型，只改切分与索引。方法本身不新——按事件分段、双流互补在视频理解里都有人做过——但把它做成 agent 的记忆底座、并给出时延与召回两个工程指标，是可复用的形态。要注意口径：45.7% 与 97% 都是官方自测，没有第三方复现，也没有公布测试集与基线配置。对做长视频 agent 的团队，值得抄的是「按事件而不是按时间切」这个约束，以及双流互补的判据设计。

Together AI 用 agent 持续编译推理引擎：24 小时把前沿模型吞吐最高提升 2.6 倍

11 月 4 日，Together AI 发布 Together Compiler（TKCC），把推理内核优化从「编译问题」改写成「agent 搜索问题」。输入是流量形态、模型与硬件，输出是一串针对推理引擎的优化方案，由一组 agent 反复生成、验证、迭代。

数字：在不到 24 小时里，TKCC 把 Kimi K3、GLM 5.3、MiniMax M3.1-Flash、DeepSeek v4.1-Flash 等前沿开源模型的 TPS 最高提升了 2.6 倍；在 SemiAnalysis 的 InferenceX 低延迟设置上创下新纪录——MiniMax M3.1-Flash 1111 TPS、DeepSeek v4.1-Flash 1205 TPS；在经典的 Llama 1B、batch size 1 场景下，比现有开源 mega-kernel 高 1.7 倍。

三个关键设计。第一是「常驻引擎」：现有 agent 优化系统每试一个想法都要重启 vLLM、SGLang 或 TRT-LLM，而引擎启动要几十分钟，实验吞吐被卡死；TKCC 让引擎只启动一次，之后热加载候选前向，不重启。第二是保真度：不拿随机输入测 kernel——MoE 与稀疏注意力的优化效果依赖输入分布，必须用真实流量测。第三是自研成本模型来选择并行策略（TP、EP、DCP 等），避免为每一种组合都实际跑一遍。

Together 说 TKCC 已在部分 serverless 生产端点运行，并把这套方法泛化到天气建模、PDE、时序与生物模型等非语言模型负载上。

看点推理优化的瓶颈从来不是「有没有更快的 kernel」，而是「试一个想法要多久」。TKCC 的实质是把实验循环从「几十分钟重启一次」压到「秒级热加载」，于是 agent 能在 24 小时里试完人类专家几个月的组合。方法可复用的前提有两个：引擎要支持前向热替换，评测要用真实输入分布——否则优化出来的 kernel 在 MoE 路由偏斜时会退化。对自建推理的团队，这是今年最值得抄的一张架构图；对模型厂商，它意味着「发布即最优」的窗口在缩短。

招商局狮子山实验室发布 Lion-ER-35B-A3B：激活 3B 参数，十项具身基准全线提升

11 月 4 日，招商局先进技术研究院下属狮子山人工智能实验室发布具身推理视觉语言模型「驭物 Lion-ER-35B-A3B」。模型采用 MoE 架构，总参数约 35B，每个 Token 仅激活约 3B 参数，基座是 Qwen3.6-35B-A3B。

它的路线不是堆数据，而是「先定义能力，再反向造题」。团队把具身推理拆成实体、空间、时序、物理、可供性、任务、社会、证据 8 个一级领域、39 项二级能力，形成一张能力蓝图；再用「能力编译」把每项能力落成「需要什么场景、怎样组织观察、提什么问题、依据什么定答案」。监督训练集共 312,380 条样本，训练预算按能力需求分配，而不是按数据源的题量分配。

错题直接反哺数据。评测发现短板后，团队从覆盖 31 个数据源、约 430 万条记录的素材池里检索「推理逻辑相同、场景不同」的新素材，构题核验后加入训练，再评测验证——他们把这套闭环叫 Eval-Driven Data Harness。

结果：十项公开具身基准全部上涨，等权综合均分 65.29（avg@4，即每题独立作答 4 次取平均）。分项上，Where2Place 空间放置 64.28（比基座 +9.30）、ERQA 具身推理 64.38（+6.19）、SAT 空间推理 89.33、ERQA 轨迹理解子类 68.18（+12.12）。四道公开题展示了它比基座强在哪：从两帧画面判断相机朝哪边转、从四条轨迹里选出真能碰到目标的那条、靠三张照片还原拍摄者方位、判断长程任务当前步骤是否完成。

看点这条研究的价值是「数据从哪来」的另一种答案：不追规模，先定义能力，再反向造题。31 万条监督样本不算大，但每条都挂在 39 项能力中的某一项上，评测错题直接变成下一轮的数据需求——这是把「数据飞轮」写成工程流程，而不是靠堆量。口径要看清：十项都是公开基准，等权均分 65.29 没有和同参数量开源模型做全面对照，只与基座和 27B 版本对比；「部分指标超过更大模型」是选择性陈述。能否复现，取决于能力蓝图与构题规范会不会公开——目前还没看到技术报告。
