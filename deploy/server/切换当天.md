## 2. 配 80 的 vhost（仍不碰 DNS）

```bash
# 本机
scp ~/deepseek-harness/web-kaixinguor.com/site/deploy/server/kaixinguor.com.nginx.conf \
    root@39.107.233.27:/tmp/kaixinguor.com.conf
```

```bash
# 服务器上
sudo cp /tmp/kaixinguor.com.conf /etc/nginx/sites-available/kaixinguor.com
sudo ln -sf /etc/nginx/sites-available/kaixinguor.com /etc/nginx/sites-enabled/kaixinguor.com
sudo nginx -t && sudo systemctl reload nginx
```

用 Host 头验证（不依赖 DNS、不依赖证书）：

```bash
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: kaixinguor.com' http://127.0.0.1/        # 200
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: kaixinguor.com' http://127.0.0.1/feed.xml # 200
curl -s -H 'Host: mathster.cn' http://127.0.0.1/ | head -3                                  # 仍是 Aiseum
```

> 模板只写 80，443 留给 certbot；**不要**在模板里手写 `ssl_certificate`
> （aiseum 那次覆盖配置退回旧证书路径，HTTPS 直接挂）。

## 3. 切 DNS（Cloudflare → 灰云）

Cloudflare → DNS → Records，改两条：

| 类型 | 名称 | 内容 | 代理状态 |
| --- | --- | --- | --- |
| A | `kaixinguor.com` | `39.107.233.27` | **仅 DNS（灰云）** |
| CNAME | `www` | `kaixinguor.com` | **仅 DNS（灰云）** |

- 一定要灰云：HTTP-01 校验要直连源站；也避免 CF 免费节点绕一圈到国内反而更慢。
- **不要动 MX / TXT**：Email Routing（`route1/2/3.mx.cloudflare.net`）和 SPF 跟 A 记录无关，
  换了 A 记录邮件照旧。
- 等生效（通常 1～5 分钟）：

```bash
dig +short kaixinguor.com        # 39.107.233.27
dig +short www.kaixinguor.com    # 39.107.233.27（或 CNAME 后解析到它）
```

此刻到第 4 步之间是“证书空窗”：浏览器会报证书名不符，属正常，几分钟。

## 4. 签证书

```bash
sudo certbot --nginx -d kaixinguor.com -d www.kaixinguor.com --redirect
```

- 首次会问邮箱、要同意条款；选 **Redirect**（80→443）。
- 前提：`certbot` 与 `python3-certbot-nginx` 已装（`certbot --version` 有输出即可；
  没有就 `sudo apt install -y certbot python3-certbot-nginx`）。
- certbot 会自己往 vhost 里写 443 块和证书路径，**之后不要再用仓库模板覆盖它**。
- 确认自动续期：

```bash
systemctl list-timers | grep certbot
```

## 附录 A：唯一会坏的功能 —— 许愿池表单

`wish.html` 提交到 `POST /api/wish`，这个接口**只存在于 Cloudflare Worker**（`worker/index.js`）。
nginx 上没有这个路由，切换后表单会 404。三个选择：

1. **先接受**：页面本身还能打开，表单下方留着微信二维码，想聊的人能扫码；
2. **保留一个 Worker**：给 `api.kaixinguor.com` 单独挂 Worker（DNS 仍走 Cloudflare，橙云），
   把 `wish.html` 里 `fetch('/api/wish')` 改成 `fetch('https://api.kaixinguor.com/api/wish')`，
   并把 CORS 放开到 `kaixinguor.com` —— 合法，接口不涉及备案拦截；
3. **服务器上自建**：nginx `location /api/wish` 反代到一个小 Node 服务，多一个要维护的进程。

## 附录 B：切完之后 Cloudflare 那层没了

灰云 = 不代理，以下能力同时失效：CF 的缓存、WAF/防火墙、图片优化、`_headers` / `_redirects`
（后两项 nginx 配置里已复刻）。需要的话日后可以改回橙云 + SSL 模式 Full (strict)。

## 附录 C：加 vhost 后默认站会变

`/etc/nginx/sites-enabled/` 按文件名排序加载，`kaixinguor.com` 排在 `mathster.cn` 前面，
所以**裸 IP 访问**（`http://39.107.233.27/`）会从“跳 mathster”变成“serving kaixinguor”。
带 Host 的正常访问不受影响。想固定默认站，在 mathster 的 80 块里加 `default_server`
（改之前先备份，那条配置正在线上跑）。
